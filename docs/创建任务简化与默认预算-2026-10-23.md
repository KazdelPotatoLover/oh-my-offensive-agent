# 创建任务简化与默认预算

> 历史记录：本文描述 2026-10-23 早些时候落地的两字段表单，以及当时的 240/600/30 分钟默认授权。该探索默认授权已被 [预算与探索血缘交付记录](ARTEX预算与探索血缘纠偏-交付记录-2026-10-23.md) 取代。新探索任务使用 `agent_limits.v1`：默认 3 个 Worker、任务不限时、不设模型/工具总次数硬上限。下文表格中的 240/600 等数字只说明当时的历史策略。发现模式且未开启探索的创建仍保留该有界授权。

日期：2026-10-23。

## 用户流程

普通创建流程只填写任务目标和授权网站地址。任务名根据目标第一行生成；模型继承服务器连接；带路径和查询参数的网址直接作为入口，不再要求用户拆成 origin 和种子路径。

高级设置默认折叠，仅在需要时修改任务名、并发 Worker 数、运行时长或启用隔离命令。能力 JSON、模型别名和本地演示等开发选项再折叠一层。默认使用服务器真实模型；未配置模型时明确提示，不能悄悄切成演示。

创建过程中隐藏旧 Run 的暂停、代次控制和追加授权栏。手机端普通表单可直接看到提交按钮，高级选项展开后可滚动。

## ARTEX 参考与差异

实际核对的参考源码：

- `ARTEX/web/src/app/(main)/function/tasks/page.tsx:CreateTaskSheet`：任务超时、心跳等放在默认折叠的高级设置。
- `ARTEX/server/manager.go:Workers`：从全局设置读取 Worker 数，缺省 3。
- `ARTEX/server/server.go:agentMaxTurns/agentRunSeconds`：读取 Agent 级单次执行配置。
- `ARTEX/agent/worker.go`、`ARTEX/agent/wrapup.go`：SDK 局部额度与独立收尾。
- `ARTEX/server/engine.go`：局部额度耗尽写为 exhausted，再通知 Planner。

本轮当时学习“任务继承默认、执行参数归运行时管理”的机制，没有新增一套 Agent 设置页面。下文默认值是该历史策略。后续纠偏已为新探索任务接上 ARTEX 式的可选期限和可选硬上限；原子预算准入、execution epoch 与授权账本仍然保留。

## 后端统一默认值

以下表格是当时的历史授权，不是当前新探索任务的默认值。当时入口为 `backend/internal/config/exploration.go`，应用于显式探索和发现模式。发现模式且未开启探索的创建现在仍走 `LegacyManagedBudget()`，数字与下表一致。

| 项目 | 默认值 |
| --- | --- |
| 并发 Worker | 3 |
| Run 最长运行时长 | 1800 秒（30 分钟） |
| Run 模型 / 工具次数硬上限 | 240 / 600 |
| Worker 单轮模型 / 工具次数 | 20 / 60 |
| Worker 单轮探索时长 | 300 秒 |
| Planner / Main 模型预留 | 默认 24 / 8 |
| Planner 轮数 / WorkItem 上限 | 32 / 48 |

自动预留以最终模型总额度为基准，分别不超过其十分之一、三十分之一，避免任务显式缩小总额度后被默认预留挤占。专家通过任务/API 明确指定的正数预留仍保留。其他请求超时、收尾和输出大小保护沿用既有默认值。

这是本次批准的新任务默认授权，不是调度性能结论，也不是用增大额度修复调度失败。保留已存在的显式小预算测试，验证局部耗尽后仍由 Planner 处理。

优先级：内置默认 → `OMA_EXPLORATION_BUDGET` 全局覆盖 → Task 配置 → 本次创建请求。全局变量为可选 BudgetConfig JSON，不认识的字段、负数及非法并发数会报错，启动时也会检查。管理员可以一次性设置 Worker 单轮额度等内部参数，普通用户不需要接触。

前端从 `GET /api/runtime/defaults` 读取默认并发、时长和模型是否配置；接口不返回连接地址或凭据。普通创建请求不发送整套默认预算；高级输入留空时不发送字段，正数才覆盖。新增 UI 不提供“0=无限”，API 的预算零值仍按省略处理（显式并发 0 仍拒绝）。

最终完整预算同时冻结在 `execution_input.budget` 及执行配置中。更新全局配置、页面刷新、幂等重试和恢复已有 Run 都不会自动放大原授权。非探索的历史创建流程仍使用原默认值；历史 Run 缺少 Worker 字段时恢复为 1 的兼容规则不变。
