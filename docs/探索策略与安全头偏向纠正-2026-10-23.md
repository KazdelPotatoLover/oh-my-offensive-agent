本工程的固定规则目录是历史配置审查扩展，不是 ARTEX 的要求。此次学习的是它的规划与知识分类机制，保留旧规则和审核记录用于兼容。

## 最终行为

- `explore` 与 `active_probe` 默认 profile、工作台新任务均不再启用 `run_security_check`。默认 `explore` 补齐受控 `http_request` 与共享流量查询能力。
- 新探索任务即使通过 legacy work type 派配置检查，也必须有冻结 profile 显式启用该能力，否则整个计划原子拒绝。非探索的旧规则流程及已冻结的显式能力保持兼容。
- Planner 不再收到安全头规则示例，也不再把开放意图限制为“逐页采集后固定检查”。提示词要求依据实际影响深入已有入口、区分有依据的后续步骤与重复基线、复用同方向会话。
- Worker 与 finding-verification 指引将加固缺失、指纹和通用错误页合并为事实；同根因的不同页面或文件作为影响证据合并，不重复计数。实际可利用的头部机制仍按相应漏洞类别验证。
- 模型工具必须明确选择 `source_kind`；API/服务调用省略时默认 speculative/unverified。普通漏洞上报入口拒绝 `security_misconfiguration`、`configuration_risk`、安全头、版本指纹和通用错误处理等观察类别，返回 `record_fact` 指引。保留原有来源、范围、收据、Epoch 和审核约束。
- 发现列表及报告优先展示实证发现，并按严重程度排序。收尾报告区分来源与验证状态；不再把“未跑可选规则”列为全站“未检查资产”。
- 新工作台创建默认主动验证，允许同源 GET/HEAD/OPTIONS/POST/PUT/PATCH/DELETE；高级设置可选只读 GET/HEAD。链接发现仍使用 GET。旧 Task/Run 的网络策略与历史发现不回写。
- 新快照记录提示词版本 v5、工具版本 v3。不增加数据库迁移。

## 工程边界

价值排序、同根因合并和探索路线选择主要由提示词策略实现，与 ARTEX 的对应机制一致。本轮没有实现任意自然语言漏洞的自动证明或通用语义去重。服务端能拒绝已知观察类别、核对真实来源，不能凭一个模型提供的类别判断所有自然语言描述是否构成漏洞。配置审查显式开关、来源约束和冻结网络授权属于本工程适配。

默认能力移除不删除历史规则实现或旧审核数据。已有 Task 显式保存的 profile 及 readonly 策略保持原值，重用旧 Task 不会自动变成主动验证任务。
