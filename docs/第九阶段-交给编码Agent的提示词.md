必须遵循以下边界：

- CheckResult、原始证据和 Finding 来源内容不因审核改变。仅更新审核状态、版本和摘要，同时追加不可覆盖的审核历史。
- 审核是独立服务事务，允许审核运行中和已经结束的 Run，不重启 Engine，不修改 Run 终态/结束原因，不使用模型或工具预算。
- 沿用 pending_review / confirmed / false_positive / ignored；所有人工状态转换必填理由，允许修正和重新打开。没有认证系统则显式使用自报审核人并说明其限制。
- 采用 Finding 行锁、expected_version 和 request_id；并发覆盖返回 409。同幂等键同内容只写一次，不同内容冲突；幂等识别先于版本冲突，历史请求重试不能重做转换。
- 校验路径 Run 与 Finding 归属；状态、版本、审核人、理由均校验；事务失败不得留下半条审核。缺失 expected_version 不得默认为 0。
- 重复检查复用 Finding 时不重置已审核状态。不要给模型新增修改人工审核结论的工具。
- 保留结束时执行总结，提供从数据库生成的当前审核报告，按四种状态分类，统计与列表使用一致快照。修正现有 summary.go 中将所有 Finding 固定标为待审核的逻辑，历史报告标明快照语义。
