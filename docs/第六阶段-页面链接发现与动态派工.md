# 第六阶段：页面链接发现与动态派工

> 当前目标调整：用户已提供现成靶场 `http://192.168.77.88:7780/`。实际演示以[接入现有靶场补充说明](第六阶段补充-接入现有靶场.md)为准，无需为演示启动 fixture。本文的 fixture 场景保留为本地自动化测试要求；补充说明覆盖下面固定地址、固定三路径和修改演示服务的要求。

## 1. 目标与前置修复

只给系统一个起点：首页。系统实际读取首页，从响应中的链接发现登录页，再从登录页发现健康检查端点，登记来源并安排后续读取。

本阶段不新增通用网络扫描、外部目标、登录操作、漏洞利用、Shell、浏览器执行或 MCP。复用本地 fixture、GET 工具、资产库、Planner/Worker 与证据流程。

开始前先验证第五阶段验收报告中的两个修复：正文读取错误必须返回可区分的不完整结果；证据存储与模型上下文长度预算分开。将验收目录的三个复现用例纳入正式测试，并验证通过，以实际测试结果确定修复状态。

## 2. 两个集合必须分开

现在用户勾选端点后，创建 Run 会一次关联这些已知资产。自动发现模式需要区分：

| 集合 | 含义 | 本地演示 |
| --- | --- | --- |
| seeds | 开始时已知、可以先访问的入口 | 只有 `/` |
| discovery_policy | 本次允许发现并进一步读取的边界 | 固定本地 origin，允许 `/`、`/login`、`/health` |

允许范围是上界，不是已发现资产清单。创建自动发现 Run 时，RunAsset 只包含首页；即使全局资产库因过去的执行已有登录页和健康检查页，也不能自动关联进来。

discovery_policy 保存为不可变 Run 输入快照。origin 为配置好的 `http://127.0.0.1:<fixture端口>`，方法固定 GET，允许路径为精确集合。本阶段不允许模型修改这个策略，也不自动采用“整个域名都可以”的规则。

旧的手工选择端点模式继续使用原流程。前端新增明确的“从首页发现”模式，同时展示起点和允许范围。不要把旧 Task 的 scope 静默改成新语义。

## 3. 完整执行流程

```text
Run 初始只关联首页
→ Planner 安排读取首页
→ Worker 调 get_endpoint，保存真实响应
→ Worker 调链接提取工具，读取已保存的响应正文
→ 程序解析、校验并登记新端点及其发现来源
→ Planner 从数据库看到新资产，安排读取登录页
→ 登录页响应中发现 /health，重复同样流程
→ 没有未处理资产，Planner 提交有证据的汇总与结束建议
```

每一批新资产都来自真实工具输出，不能由 Engine 或 MockProvider 预先填满。Worker 完成当前工作后退出，由下一轮 Planner 决定后续工作。这一阶段检验的是根据新增信息继续派工的能力。

## 4. 调整 fixture，让发现可以验证

首页 HTML 加入实际 `<a href="/login">` 链接；登录页 HTML 加入实际 `<a href="/health">` 链接。健康检查继续返回 JSON，不包含新链接。

增加重复链接、返回首页的循环链接，以及用于验证过滤的链接，例如同 origin 的 `/outside-scope`、另一个端口或外部 origin、`mailto:`、`javascript:`。这些候选不能被访问。

提供受控 fixture 配置，能移除首页到登录页的链接。移除后新 Run 只能处理首页，不能仍自动出现登录页和健康检查页。恢复后，后续 Run 能再次发现它们。配置只影响演示应用，不改变任务的允许策略。

## 5. 链接提取工具

新增 `extract_endpoint_links(source_tool_call_id)` 或语义等价的领域工具，负责解析已有证据；它不发送 HTTP，也不接受模型传入任意候选 URL 或正文。

服务端校验 source_tool_call：

- 属于当前 Run、当前 Worker Session/Attempt。
- 是成功的 get_endpoint，来源资产属于当前工作。
- 结构化证据完整、可解析，正文为支持的 HTML；正文读取失败或截断时不把解析结果当成完整发现。
- Run 仍允许运行；stopping 和终态不再接受发现提交。

使用 HTML 解析器处理 `<a href>`，不使用模型猜链接，也不通过全文正则扫描任意字符串。相对地址使用来源请求的真实 URL 解析，不使用模型描述；本阶段忽略 `<base>`，不执行 JavaScript、不处理表单动作。

规范化之后逐项检查：协议、数字主机、精确端口、GET 与允许路径。路径保留大小写和尾斜杠语义；纯 fragment 链接跳过，本阶段 query、用户信息和不支持协议的链接明确拒绝。任何重定向仍不自动跟随。

返回新发现、已存在、被拒绝三组结果，拒绝项保留原因。对每次最多解析的 href 数量和字符串长度设上限，避免无限输入；初始可设每次最多 100 个 href、单个 2 KiB。

## 6. 资产登记与发现来源

沿用现有资产唯一身份，按规范化 GET + URL 去重。首次在本 Run 发现且通过策略检查时，关联 RunAsset 并保存非敏感快照；不通过策略的候选只保留拒绝说明，不进入可执行范围。

建议增加轻量 AssetDiscovery 关系，至少表达：run_id、source_asset_id、source_tool_call_id、target_asset_id、原始 href 与发现时间。重复调用同一来源、重复 href 不得产生重复发现关系。

来源资产和目标资产是两个不同角色。例如：读取首页的 ToolCall 证明“首页包含 /login 链接”，此时还不能证明登录页实际返回了什么。

可以复用已有 Observation 表，在来源首页资产上记录 `discovered_links`，其来源为读取首页的真实调用，data 中引用新发现的目标资产 ID。后续工作用该观察的 ID 填 source_observation_ids。不要把读取首页的调用错误绑定为登录页内容的证据。

资产登记、RunAsset 关联、发现关系、相应观察和事件在短事务中一致提交。与停止流程使用一致锁顺序，网络请求和 HTML 解析不占用长期数据库事务。修改共享资产元信息不能改写过去 Run 的证据快照。

## 7. 动态派工与结束条件

Planner 每轮读取当前 Run 的已发现资产、已有工作、发现来源和必要观察。它只为尚未安排的资产生成读取工作，使用稳定的工作 key，不能凭猜测创建允许集合中的其他资产。

提供一个新的工作类型或角色工具组合，允许 Worker 完成 `get_endpoint → extract_endpoint_links → 记录响应观察`。汇总工作仍只读已有数据。

当前 Mock 的 HTTP 演示在单端点范围内也可能生成重复的 Home/Health 工作，本阶段应改成按实际资产 ID 与待处理状态生成计划。Mock 验证业务协议和结果，不承担 HTML 解析，也不能提前硬编码派发完整三端点链。

Run 的总模型请求、工具请求、规划轮数、工作数和时间预算继续覆盖所有轮次。发现新资产时要触发下一轮规划；同一 Run 不并发运行两个 Planner。循环链接、重复提取和重复规划不会无限扩大工作。

没有更多链接，不等于整个应用已全面检查。结束报告表达“在当前策略与已取得页面中，链接发现已收敛”，列出实际读取、发现、拒绝、失败和因预算未处理的对象。

## 8. 界面与使用方式

Run 详情展示种子资产、允许策略、已发现资产以及来源。资产详情显示“通过哪个页面、哪次实际响应发现”，点击可打开那份响应。

用列表与展开即可：

```text
首页（用户提供的入口）
  → 登录页（来自首页响应中的 /login）
      → 健康检查（来自登录页响应中的 /health）
```

同时显示候选被拒绝的原因。不要把候选出现、登记成功、HTTP 读取成功和漏洞确认合并成一个状态。本阶段只完成页面端点发现与读取。

## 9. 验收任务

交给实现 Agent：先修复第五阶段已复现的缺陷，再按本文完成第六阶段，分为前置修复、发现与来源、动态派工与界面三个可运行提交。保留已有模式与数据，不覆盖当前未提交实现；使用版本化迁移。

必要验收包括：

1. 启动后，当前 Run 初始仅有首页；不能借用全局已有资产预填全部端点。
2. 默认链接下，真实 HTTP 请求顺序符合发现链：先首页，再登录页，再健康检查。
3. 去掉首页链接，新 Run 不读取或关联后两个端点；恢复链接后重新发现。
4. 循环和重复链接不会重复创建资产、无限派工或重复读取同一项工作。
5. 范围外路径、端口、origin、query 与不支持协议在网络请求前被拒绝；用第二个本地服务计数为零验证没有越界。
6. 发现关系能追溯到真实 source ToolCall；跨 Run、Session、失败调用、错误来源被拒绝。
7. stopping 后不再登记新资产或派工，预算耗尽明确保留部分成果。
8. 前置三个回归测试及既有测试通过，前端类型检查通过，浏览器实际展示一次完整发现链。

数据库测试使用独立 TEST_DATABASE_URL。真实模型验证与 Mock 驱动的真实 HTTP 验证分别报告。交付实际测试与页面结果、允许策略的定义、已知限制，不仅交截图和完成说明。

学习验收：负责人能解释“种子与允许范围的区别”“发现链接与访问成功的区别”“为什么每个新资产要有来源”，并能在页面顺着首页到健康检查查看真实发现链。
