## 3. 保留什么，改变什么

保留 Task/Run/事件、事务与幂等、范围策略、资产规范化、原始工具证据、Provider 两种协议、现有检查和审核历史、停止与迟到写入保护、独立测试库机制。

本轮替换/补齐：

- 固定工作菜单独占规划能力 → 开放意图 + 注册执行能力，现有类型保留为专用适配器。
- 整批完成后规划 → 常驻单 Planner + Worker 池，有效事件/心跳触发。
- 一项工作实际只执行一次 → 稳定 WorkItem，多 Attempt、Worker 记忆与有界续派。
- 页面链接图充当知识模型 → 资产图与探索图分开，事实/目标/证明有真实关系。
- 工作清空便可建议成功 → 明确目标、证据与不可达/受阻/部分完成结论。
- 日志只供人看 → Agent 可查询的过程记忆与知识读工具。
- 人工只改 Finding 状态 → 对执行与方向的独立控制，另有独立复测。

不要用删除 work_type enum、给全部 Agent 开 Bash、增加一张图形页面或复制旧 Run 来代替这些机制。

## 4. 目标对象与职责

| 对象 | 职责与不变量 |
| --- | --- |
| Task | 用户任务定义与当前可编辑配置 |
| Run | 一次持续推进的探索实例，固定目标/范围输入；允许受审计的恢复 |
| ExecutionEpoch | 一次 Engine 执行代次，防止旧调用污染恢复后的执行 |
| Goal | 最终交付结果及验收条件；不是“发起请求”这样的动作步骤 |
| WorkItem / Intent | 稳定工作方向、理由、锚定资产和来源事实 |
| Attempt | 某方向的一次执行，独立预算/原因/输出，不复活旧记录 |
| AgentSession | 本轮 Planner 或 Worker 的执行记录与消息增量 |
| Conversation | 同 WorkItem 的连续 Worker 对话，消息保留原执行归属 |
| PlannerTodo | 跨规划轮次的便签/串行计划，不能取代数据库可执行条件 |
| Observation | 原始工具输出的解释/摘录，保留来源，不天然等于事实 |
| Fact | 可引用的知识陈述、observed/inferred、证据、状态与版本 |
| Hint | 人或 Agent 提供的线索/假设，不自动当作已验证事实 |
| CheckResult | 现有注册检查的计算结果，原始含义和证据不改写 |
| Finding | 发现/候选发现的业务对象，来源、验证与处置语义分开 |
| Asset / AssetRelation | 规范化资产身份与真实对象关系 |
| ExplorationNode/Edge/Anchor | 探索链及资产锚点，链接规范对象而不复制其权威状态 |

可以使用统一探索节点或类型化实体加关系表，但必须规定唯一权威数据源。WorkItem 是可执行状态的权威；若图中有 intent 节点，唯一关联 WorkItem，状态从它读取，不维护两套会独立漂移的状态机。

工作硬依赖与探索血缘不同。前者决定能否领取并禁止依赖环；后者解释推理来源，不把整张页面/知识图强行限制为 DAG。

## 5. 全局工程约束

1. 同 Task 的活动执行唯一性保留，暂停是否占用该资格在迁移和 API 中统一定义；同 WorkItem 最多一个活动 Attempt，同 Run 最多一个有效 Engine。
2. 新状态、动作、边类型、工具 schema 均服务端校验。所有接受/拒绝原因、执行版本、来源可审计。
3. Planner 决定值得做什么；Engine 决定能否执行；Worker 只推进领到的方向。提示词不能替代范围、预算或来源校验。
4. 不自动重复已成功工具；未知结果不当成功；数据库幂等不等于外部动作恰好一次。
5. 原始输入、证据、Attempt 历史和人工审核不改写；发现的审核结论、执行完成与安全验证分开。
6. 原注册工具作为兼容能力存在；旧执行快照保持旧含义，新模式记录新的 prompt/tools/schema 版本，不能改变历史快照伪装成已使用新机制。
7. 所有业务写入与事实事件同事务，提交后通知；事件可重复消费但效果必须幂等，通知只是加速信号，不是唯一事实来源。
8. 当前数据库会被其他人使用，不跑清表测试、不直接修历史状态、不为演示污染开发库。测试专用 fixture 与新建独立库，真实模型/靶场另行授权。

## P1：分层预算与可恢复 Worker

细节参照第十阶段 A–C，以下是必须落地的行为。

### 数据与运行时

- 增加 Worker Attempt 与 Planner 单轮探索/settlement 配额。每个真实调用同时接受局部与 Run 总额校验，gate 返回类型化作用域和原因。
- Conversation 唯一绑定 Run/WorkItem；Session 记录本轮增量和恢复点。attempt_number 在锁下递增，唯一活动约束兜底。
- 新 Attempt 加载同工作原始消息，保持 Responses NativePayload 与两种协议的工具配对；未执行、失败、结果未知分别表示。历史只引用，不重新 INSERT 成新调用。
- 局部超时转到有界收尾；Run context 仍有效且总额度允许时可保存已有知识，不能新发探索请求。用户停止/全局截止优先。
- 已有成功证据同 Run 复用，完成判定绑定 WorkItem 的实际目标；不能因本轮无新观察误判失败。

### 控制与规划

- continue_work_item / retry_work_item 共用事务：校验 expected_attempt/version、状态、范围、剩余总额和幂等键，旧 Attempt 保持终态。
- Planner 新一轮 Session 读取当前态势与共享 PlannerTodo，不恢复全体旧规划聊天。Todo 保存数据库支持重启是本工程增强，标注与 ARTEX 进程内 store 的区别。
- 提供 trace/output 基础查询，Planner 可读实际进度；有续派次数和无进展阈值，不允许改 key 绕过。
- 上游 exhausted 时依赖等待，继续/完成后系统 dependency-blocked 可重新计算，人工阻塞不被自动解开。

### 验收门槛

同 WorkItem 第一轮局部耗尽，其他 Worker 继续；Planner 有依据地续派，第二轮恢复原消息并完成；HTTP 成功采集只发生一次。两种协议、并发认领、部分工具批次、数据库提交后响应丢失、迟到旧 Attempt、停止中途和零进展循环均有反例测试。

## P2：双图、目标和证据驱动的结束判断

### 资产图

- 在现有资产表上增加类型化关系，支持至少站点/app、endpoint、host/IP/service 等基础身份；归一化与去重由程序计算。
- 资产全局共享但可见/可执行范围需服务端过滤，登记到图上不等于获得执行授权。
- 当前资产元数据与采集时证据快照分开；已有资产更新不能使旧报告中的采集事实悄悄变化。

### 探索图

- 增加 Goal、Fact、Hint 及与 WorkItem/Finding 的节点关联，边与资产 Anchor。
- 至少表达 origin→目标/初始方向、事实→方向的 derived_from、方向→事实/发现的 yields、事实/发现→目标的 proves。接口明确方向、类型与来源校验，数据库不接受任意越 Run 连接。
- 一个方向可由多个事实共同产生；同一资产可被多个不同方向锚定。页面链接仍留在 asset_discoveries，不伪装成探索推理。
- Fact 区分 observed/inferred、证据集合和确认/撤回/失效状态；修改以版本/审计表达，不能清空历史。只重复已有陈述不能算新增进度。

### 目标与知识工具

- 增加 set/list_goals、record/list_facts、record_hint、node_detail、graph_overview、prove_goal 等服务与角色工具。
- Goals 从用户最终交付物提取，不把扫描步骤当目标；可由模型建议分解，但不能臆造新授权范围。约束结构化保存并明确来源，原范围策略仍是执行边界。
- prove_goal 校验目标/证据归属与状态、理由、验收规则版本；计数/范围等可程序验证条件由服务端验证。任意自然语言判断仍显示为 Agent 判断，不能宣称数学证明。
- 证据撤回或目标变化使原证明需复核/失效，保留旧 proves 记录和解释，不让过时证明永久维持成功。
- 新探索模式禁止无证明直接用 suggest_completion 宣称成功；保留旧模式兼容入口，但新快照不能绕过目标检查。无工作可跑而目标未达成，返回 blocked/partial/needs_input 等明确业务结论，不当 completed 目标达成。

### 验收门槛

两个事实共同派生一条方向，生成新事实并证明其中一个目标；另一个目标未满足时不能完成任务。错误来源、inferred 证据、撤回事实、跨 Run、重复边、同资产不同方向均有测试。能从目标追到事实、工作、Attempt、工具及资产。

## P3：开放意图和持续规划调度

### 意图与执行能力解耦

- 在保留现有适配器基础上新增通用意图执行模式：目标/理由/来源事实/资产/优先级/执行 profile。
- profile 由配置注册工具、能力与额度，Planner 只能引用已存在并被授权的 profile。意图文本不直接成为 shell 命令，页面内容不能更改授权。
- 去重保留服务端稳定 key，并记录目标、规范化资产、方向类别/判定条件和来源事实版本等可比较身份；同方向重派需说明新的材料性依据。不能仅换 title/key 就绕过已有 open/running 工作、续派上限或无进展止损；不宣称已解决任意自然语言语义去重。
- Worker 在单一意图内选择多个已提供工具推进目标，路径不是预先写死的“读页→抽链接→规则”；新方向交 Planner，事实和资产写回各自存储。
- 对原 submit_plan 的兼容集中在适配层，不新增一套独立 Engine 或绕过旧停止/预算/审计。

### 常驻调度

- 将批次式 dispatchWorkers 改为单 Planner loop + 有界 Worker pool。有效事件至少覆盖工作终结、增量 Fact/资产、Finding、Goal、Hint、人工干预。
- 事务提交后发信号，合并短时变动；持久化事件游标/版本和必要心跳防漏唤醒。发生变化不等于必调模型，去重后的有效变化与预算策略共同决定。
- Planner 本轮可以 wait、continue、派新方向或证明目标；有工作在推进时 0 新意图是合法结果。全局无工作且目标未达成时做明确的继续/换路/受阻决策，不能空转或假成功。
- Worker 途中写回重要事实可唤醒 Planner，其他 Worker 不需全部退出；Planner 不能重派已在处理的相同方向。

### 验收门槛

长 Worker A 未结束时提交新事实，Planner 被唤醒并派 B；等待依赖的一轮允许无新工作；事件突发被合并；漏通知可从持久化事件/心跳恢复。两种不同目标在相同工具集合上选择不同合法组合，生产逻辑不得按 fixture 页面名硬编码。

## P4：过程级协作、工作空间与上下文

### Trace 与知识按需读取

- 为现有模型/工具/活动记录建立可查询的 trace index，保留 Run/WorkItem/Attempt/Session、步骤、类型、来源、错误和完整输出引用。
- 提供 list_worker_traces、search_all_worker_traces、get_worker_trace(step_ids)、get_worker_output；先摘要再按步骤取全文，分页/上限/截断提示明确。
- 同 Run 的其他 Worker 可检索有权限过程，默认排除自己；跨 Run/Task 无授权拒绝。不能只在前端做“显示日志”就算完成 Agent 协作。
- Planner graph_overview 分层返回当前状态、增量和证据指针，避免每轮把所有 observations 和原始响应塞入提示词。

### 工作空间与长输出

- Run/WorkItem 有明确工作目录与产物归属；长工具输出保存完整产物，模型只接收预览和受控读取引用。停机/重试后引用可用。
- 原始 transcript 与压缩视图分开，记录压缩覆盖区间、版本和来源；工具调用配对/Responses 载荷不可被任意截断。压缩故障可诊断，不无声丢上下文。
- 过程记录、知识 Fact 与最终报告是三层信息，不能用摘要替代唯一原始证据。

### 验收门槛

Worker A 的某次工具输出尚未写成 Fact，B 通过搜索命中并按步骤读取后推进自己的目标；不要求把完整 A 对话复制给 B。长输出、压缩前后续跑、分页、来源归属与越界读取均测试。

## P5：执行控制、总授权与恢复代次

### 控制协议

- 提供工作级继续/故障重试、steer、kill；steer 以带版本/确认的控制消息在下一安全边界注入，不自动修改原目标快照。kill 只停目标 Attempt，不取消其他 Worker。
- 暂停/继续整个 Run 明确状态与资格：暂停禁止新准入、结束/停妥活动 Attempt，保留记忆；恢复新执行代次。暂停不自动延长原 deadline，过期时明确需要新的时间授权。
- 用户停止不自动恢复；恢复总预算耗尽或关机 interrupted 需显式命令。其他终态的重跑规则明确区分，不用批量重开绕过。
- 人工线索写 Hint，改变正式目标/约束须留版本及原操作员意图；仅从目标文本推断不能扩大既有执行授权。

### Epoch 与授权账本

- 按第十阶段 D 引入 epoch、budget_grants、历史结果快照；原授权不改写、用量不归零、新窗口明确批准时刻和 deadline。
- 所有准入、写入、终态协调、通知游标与 Manager 注册/释放携带代次，旧响应与旧 goroutine 无法覆盖恢复后的执行。
- 追加额度只有用户能做，Planner/Worker 不能隐式续全局预算。恢复幂等、同 Task 活动执行唯一、启动失败持久化、重启撤销旧执行资格完整。
- 对现有迁移只保留旧事实并补初始 epoch，不能伪造过去的调用、授权或目标完成证明。

### 人在环路入口

UI 至少能直接提交有结构的 Hint、方向纠偏和控制命令。增加 main-agent 对话时它也只调用相同业务控制服务；不能有一条聊天捷径绕开权限、状态和预算。

### 验收门槛

纠偏恰好注入一次、kill 不影响其他工作、暂停不产生新调用、恢复保留对话和用量、总额追加不重置历史；旧 epoch 的模型/工具返回及释放不会影响新执行。双击/断线重试/重启/并发操作均有反例。

## P6：发现语义、独立验证与复测

### 分类与兼容

- 保留 CheckResult、配置候选及现有审核状态/历史。新增 source_kind/verification_state 或等价字段，区分规则配置候选、推测线索和实证发现；不复用 confirmed 表示“已成功利用”。
- 通用 record_fact 支持调查结论；report_finding 要求本次真实证据、目标资产、触发条件和可复现描述。证据归属能程序校验，内容是否足以证明仍须保留可审查边界。
- 怀疑或版本匹配保留 inferred，不自动升格。规则结果和人工审核不能自动改写为实证漏洞。

### 独立复测

- 复测创建独立 VerificationRun/Session，关联原 Finding、当次授权/目标版本/证据/结果；不重启原扫描，不改写原证据。
- 同一发现最多一个活动复测，支持停止、失败、重启后重试；结果为 still_reproducible/fixed/inconclusive 或等价明确枚举。
- 处置状态与配置审核状态分离。只有成功且符合规则的 fixed 复测才能影响“已修复”处置投影；失败/停止/无法确认不把问题当已修复。

### 验收门槛

本地 fixture 或纯本地受控行为产生可重复证据，变更 fixture 后独立复测，保留两次结果和原证据。新验证字段不破坏旧审核；已有配置问题 confirmed 仍只表示配置确认。

## P7：工具扩展、完整证据与统一页面验收

### 能力机制

- 工具按角色/profile 注册、启用、配置 schema、输出与超时；支持内置及外部适配器，不把新增能力全部塞进 work_type switch。
- 运行能力变更绑定版本和有效范围。需要命令工具时在明确执行环境与工作空间中提供，接入停止、输出保存、权限和留痕，不仅在 prompt 中写限制。
- 建立 MCP/skills 等扩展边界；具体外部服务和凭据不是本轮验收前置。用本地工具适配器证明可扩展，不要求连商业服务。
- 统一流量/证据引用：get_endpoint 与另一种受支持工具均能关联真实请求/响应或等价原始产物。若采用记录代理，处理 HTTPS 信任和证据关联，不能宣称未接代理的任意工具都已被录制。

### 页面

- Run 总览：目标与证明、frontier、活动方向、预算及执行代次。
- 方向详情：来源事实、资产、Attempt、消息/trace、续派理由、控制历史。
- 探索链/资产关系：可先用表与可点击链路完成追溯，不以炫图代替真实关系；提供可用的关系浏览入口。
- 知识与发现：Observation/Fact/Hint/配置候选/实证发现/复测及审核语义明确。
- 执行干预：Hint、继续/纠偏/暂停/停止、总预算追加，错误和冲突可见，不静默覆盖。
- 模型、工具及 profile 可配置，新任务有可直接使用的自主探索模式；旧任务仍可查看。

### 验收门槛

新增一个本地工具适配器无需修改 Planner 意图语义；两个工具路径的产物可追溯且停止有效。浏览器完成创建目标 → 看方向 → 查过程 → 干预 → 续跑 → 目标证明 → 审核/复测全过程。

## 6. API/迁移交付要求

建议按职责拆出 exploration/knowledge、goal、intent-control、conversation、trace、budget/epoch 等服务；API、模型工具和 main-agent 都调用相同服务入口。引擎负责调度，不承担全部数据校验；Provider 保持协议适配职责，不保存共享可变会话历史。旧 service/agent.go 可增量拆分，不能借此先做大规模无行为收益的重构。

接口可按现有风格命名，但以下能力必须有一致业务服务，不让前端或模型直接写状态：

| 能力 | 建议接口/工具族 |
| --- | --- |
| 目标与知识 | goals、facts、hints、graph-overview、node-detail、prove-goal |
| 意图 | intents/work-items、continue、retry、steer、kill |
| 过程检索 | traces/list、search、steps、outputs |
| 执行控制 | pause/resume/stop、budget-grants、epochs |
| 能力与复测 | profiles/tools、finding verifications/retests |

所有写接口说明必填字段、版本/幂等规则、作用域、事务、冲突码和资格；未知 404，输入 400，版本/状态/幂等冲突 409，体积超限 413，内部故障 500 不透出敏感细节。

迁移只能增量，不删旧数据/枚举偷换语义。新 FK、唯一索引、事件序号、锁顺序和回滚策略需实际验证；不可逆的数据/审计保护明确说明。历史只补可证明的关联，不为老 Run 编造事实或 Goal 证明。

## 7. 总体验收矩阵

| 编号 | 场景与必须成立的断言 |
| --- | --- |
| E1 | fixture 的路径/内容变化后，发现仍来自真实响应，生产代码无固定页面计划 |
| E2 | 局部耗尽 → 保存进度 → Planner 查 trace → 同工作新 Attempt 恢复；HTTP 已成功部分不重采集 |
| E3 | 两事实 → 一方向 → 新事实 → 证明一个 Goal；其他 Goal 未证明时不能宣称全部完成 |
| E4 | A 未结束时写出事实，Planner 及时派 B；无新方向时允许 wait；事件突发不造成模型风暴 |
| E5 | B 通过过程搜索利用 A 尚未正式写 Fact 的细节，来源可追溯、权限边界不变 |
| E6 | 相同工具在不同目标下选择不同步骤；开放意图不等于放宽范围、跳过预算 |
| E7 | 完整 Chat Completions/Responses 历史恢复，多工具中断/未知结果不假成功、不重放副作用 |
| E8 | 并发认领/继续/停止/恢复、旧 Attempt/epoch 迟到均不写坏当前状态，不超总预算 |
| E9 | 目标或证据变更能使证明需复核，历史保留；访问过/检查过/目标已证分开 |
| E10 | 人工 steer/kill/pause 与 main-agent 控制复用同一服务，冲突可见，误操作不影响其他工作 |
| E11 | 规则候选、人工 confirmed、实证验证及 fixed 复测不混淆，旧审核历史完整 |
| E12 | 原第六至九阶段的工具、发现、预算、来源和审核回归通过，旧 Run 可读 |
| E13 | 迁移从当前旧库到新版保留数据；重启保持用量/记忆并撤销旧执行资格；审计降级保护有效 |
| E14 | 浏览器按真实 UI 完成端到端；不能用 API 测试/构建成功冒充浏览器已验收 |

假模型仅用于稳定控制决策与故障，不把关键规划/恢复/证明硬编码在生产路径。并发测试使用屏障、事务锁或可控 hook，不依赖固定 sleep 撞概率。

每批完成后跑相关单元/集成/race 回归；最终运行完整适用后端测试、go vet、前端构建与 git diff --check，避免每改一行都盲目全量重跑。测试库显式新建并确认身份，不能复用开发库 URL。

## 8. 执行方式与交付清单

按 P0→P1→P2→P3→P4→P5→P6→P7 推进。每批先写契约与最关键反例，再实现和验证；依赖已具备后直接继续，不把每批结束当作需要用户重复授权的停点。

遇到缺少外部凭据时用本地适配器验证机制，继续其他独立工作；遇到真实阻碍说明具体缺项、影响范围和已完成内容。保留现有用户改动，不 reset/clean，不让真实模型与靶场成为架构验证前提。

交付至少包含：

- 实际实现、兼容迁移、可操作的前端入口和受控本地演示流程。
- `docs/验收/ARTEX对齐/进度.md`：P0–P7 状态、对应源码、实现差异、验证证据、缺口。
- `docs/验收/ARTEX对齐/架构与流程讲解.md`：从用户目标到证明/恢复/人工控制的完整工作流。
- `docs/验收/ARTEX对齐/验证结果.md`：真实测试命令、结果、浏览器证据与未验证项。
- 更新部署/迁移说明与项目主文档入口，明确哪些功能需重建前后端，区分代码完成和当前服务已更新。

默认不提交、不推送、不部署、不改写开发库历史。`AGENTS.md` 只本地保留且已排除，禁止强制加入 Git。本文不授权真实目标测试或外部消息发送。

## 9. 本轮不要求复制的周边

商业服务连接、所有 MCP/skills 插件、全套资产同步平台、复杂三维/力导向 UI、多租户企业后台和多实例分布式调度不作为本轮交付前置。扩展点与真实机制必须存在，并用本地实现证明；不能因这些周边未接而推迟核心机制，也不能把“暂不复制所有产品功能”解释成可以省略 P1–P7。
