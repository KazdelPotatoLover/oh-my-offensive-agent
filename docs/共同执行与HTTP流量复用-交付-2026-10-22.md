## 2. 实际行为

### 执行保护

`tools.Registry.Register` 包装所有工具的 Validate 和 Execute。同步工具处理函数 panic 后，服务日志保留工具名、阶段、panic 及堆栈；模型只收到通用失败。Validate panic 持久化为 failed，普通参数无效仍为 rejected。Execute panic 沿既有失败路径保存结果、配对 tool 消息、释放工具 context，不产生成功证据。

Main 使用新增 `031_main_tool_calls` 保存工具调用、所属模型调用及终态；失败写库仍会终止当前回合。panic 后有真实 failed 记录，随后允许模型继续查询。迁移 down 在存在历史时拒绝删除。没有新增常驻 Agent 或执行器。

### HTTP 来源与访问覆盖

`netcap.ReadToolExchange` 是 http_request 覆盖、发现和实测证据共同使用的来源入口，检查：Run/Epoch、网关收据、原始成功工具调用、调用引用的同一 receipt、Session/WorkItem、实际关联资产、正文哈希及响应哈希。复制输出中的 receipt 不会产生新可信调用。

`ListAssetCoverage` 将有效 http_request 的资产并入 visited，重复请求同一资产仍计一次。部分响应可以证明实际访问，不能用于完整正文发现或实测证明。访问、方向完成和确认漏洞仍是不同概念。现有 get_endpoint/read_sample 覆盖及历史 GET 证据读取保持兼容；没有将旧记录补造为新收据。

`HTTPDiscoverySource` 按当前 Session 解析稳定工具调用 UUID 或 session 内 call_id。http_request 使用通过完整性校验的捕获正文，get_endpoint 沿既有证据解析。`extract_endpoint_links` 解析该完整正文，保持同源、方向资产、深度、页面上限、去重和停止/Epoch 事务检查。对捕获 HTTP 来源还检查冻结的网络方法/路径策略；需要明确的 discovery_policy，不从网络访问授权猜测无限发现权限。已有 HTTPS 同源授权可以用于提取。

HTTP 工具发给模型的结果增加 `_execution.source_tool_call_id`；完整输出仍单独持久化。Planner 与画板的意图摘要优先非空 summary，再兼容 text；新意图同时保存两者。不增加第二套方向状态。

### 只读 HTTP 材料工具

所有工具都通过既有模型请求池和预算运行。Worker 可以读取同 Run 允许共享的脱敏材料；初始/后续 Planner 与 Main 也安装相同读工具。调用身份从服务端 Session 绑定，模型不能通过参数自报角色。Worker/Planner 的旧执行 Epoch 不能作为当前读取执行身份；Main 保留稳定主会话锚点。捕获材料允许读取 `1..current_epoch` 的历史，仍需满足冻结的请求范围和方法策略，不允许跨 Run 或读取未来 Epoch。

| 工具 | 参数与结果 |
| --- | --- |
| search_http_traffic | 可按 origin、host、url_contains、method、status、epoch 过滤；默认 5 条、最多 20 条；返回轻量索引和来源 ID。用 next_cursor 作为下一次 after。 |
| get_http_exchange | 只接受 receipt_id；返回脱敏请求/响应头、各最多 4096 字节正文页、产物 ID、来源、complete、historical_material、new_verification=false。 |
| read_artifact | 沿用原接口，按 artifact_id、offset、limit 分段。next_offset 是 UTF-8 安全的显示正文**字节**偏移。默认 8192、最多 32768 字节。 |

搜索按 `(created_at,id)` 升序使用 keyset cursor。每次最多扫描 200 个候选及一个探测项；授权/origin/host 过滤可能使某页不足指定数量甚至为空，有 next_cursor 时仍可继续。本轮不提供正文全文搜索，不引入外部搜索服务。

ID 约定：

- **receipt_id**：一个网关捕获 exchange 的稳定查询 ID；本工程不另建 exchange_id。
- **request_id**：目标请求身份，不能代替 receipt_id 调用 get_http_exchange。
- **request_artifact_id / response_artifact_id**：捕获正文的稳定产物 ID，用 read_artifact 分页。
- **source_tool_call_id**：原执行工具记录 UUID；工具提供材料来源时应保留它。某些旧/网关来源可能没有此关联，不补造 ID。
- **call_id**：上游模型的工具调用 ID，只有原 Session 内唯一；不能拿别人的 call_id 当全局来源。
- **fact_id**：record_fact 返回的图节点 ID，供 Planner 交接。读取工具自身的 ID 不能代替原始实测调用。

捕获产物保留原 SHA-256，在读取时验证原正文，再脱敏显示。source_sha256/hash_scope 指向原捕获字节；total_bytes/offset 指向显示正文。capture_truncated 与 display_limited 分别说明捕获不完整和权限/二进制展示限制。敏感正文仍沿用既有短预览限制，二进制不作为普通文本返回。普通角色不能借新增接口读取原始 Cookie、Authorization 或明文敏感字段。

查询和读取不调用网络，不增加实际访问次数，也不能作为一次新的漏洞复测证据。需要新的测量、目标变化或必要复测时仍允许 http_request；提示词中的“优先复用”是策略，不是禁止重复请求的硬规则。

## 5. 两个 Worker 的使用方式

部署本轮代码并应用正常启动迁移后，创建有合法范围的任务，设置允许的 Worker 并发。让 Planner 安排“A 获取并记录页面”和“B 分析已有页面材料”两个方向。B 可以没有新的请求资产，仅访问同 Run 共享的合法材料。

建议方向指令：“优先复用本 Run 已抓取的 HTTP 流量。A 保存真实 receipt_id、response_artifact_id、source_tool_call_id；B 按 origin/URL 搜索，用 get_http_exchange(receipt_id) 核实来源，正文还有 has_more 时调用 read_artifact，最后用原始来源引用记录 Fact。确需新的测量或复测时再请求目标。”

具体工具顺序：

```text
A: http_request(method="GET", asset_id=<已分派资产>)
B: search_http_traffic(origin=<授权 origin>, url_contains=<路径>, limit=5)
B: get_http_exchange(receipt_id=<搜索返回的 receipt_id>)
B: read_artifact(artifact_id=<response_artifact_id>, offset=<next_offset>, limit=4096)
```

不要让 B 把自身查询的工具调用当新验证证据；保留 A 的原始来源 ID。需要请求副作用/认证复测时仍走现有授权与复测校验。
