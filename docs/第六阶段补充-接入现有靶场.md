# 第六阶段补充：接入现有靶场

## 1. 用户提供的实际目标

实际演示使用 `http://192.168.77.88:7780/`，无需另建或启动 fixture。原课程中的本地 fixture 保留为可控的自动化测试环境；不对现成靶场修改页面、版本或配置。

已直接读取一次首页，返回 HTTP 200、`text/html;charset=UTF-8`，正文为静态 HTML，标题是“首页 · 启岳智造集团”。没有访问首页链接指向的后续页面，没有测试漏洞或提交表单。

首页共有 20 个 `<a href>`，规范化去重后为首页和以下 9 个新端点：

```text
/news
/products
/downloads
/about
/contact
/news/2026-q1-yanli-base
/news/2026-supplier-guide
/news/2026-park-visit-policy
/news/2026-key-customer-event
```

该清单是人工检查记录，不能预填为 Run 已发现资产或让 Mock 硬编码派工。实际程序必须从本次运行保存的首页响应中解析出它们。

## 2. 目标策略

实际运行的种子为完整首页 URL，初始 RunAsset 仅有首页。策略采用精确 origin：

```text
http://192.168.77.88:7780
```

本阶段允许读取该 origin 下从实际 `<a href>` 发现的普通 HTML 页面，方法限 GET。不同协议、主机、端口的链接只记录拒绝原因，不发送请求。不要使用字符串前缀代替解析后的 origin 比较。

以显式策略类型表达同 origin 页面发现，不要把 allowed_paths 空数组解释成“允许全部”。可以新增明确的同 origin HTML 模式，保留既有精确路径白名单模式。策略在创建 Run 时固化，模型无权修改。

演示初始限制：最多读取 20 个页面，发现深度最多 2 层（首页为 0），HTTP 并发为 1，请求间隔至少 500 ms。这些限制必须作用于实际请求，包括失败请求，不只作用于工作列表显示。总预算耗尽时保存部分结果并注明退出原因。

本阶段拒绝 query、fragment、用户信息与非 HTTP 协议。表单动作、登录尝试、提交、登出、删除等操作不在此阶段执行范围；不自动跟随重定向。链接目标若返回非 HTML，保存受限的响应元信息并跳过正文解析，不自动下载文件或执行脚本。

`/downloads` 作为页面入口可以读取；它可能包含文件链接，文件候选记录为跳过。Content-Type 仍需由实际响应确定，不能仅凭路径判断。读取范围内页面不代表执行其中的操作。

## 3. 必须解除的 fixture 耦合

当前 GetEndpointTool 限定 127.0.0.1、FIXTURE_PORT 与几个固定路径；资产创建也从内置 fixture spec 产生 URL。这些实现无法直接接入用户提供的地址。

按以下边界修改，不能删除校验后任意联网：

1. 自动发现模式从已校验的种子 URL 建立真实 HTTP 资产，而不是走“别名 → fixture 端点”的转换。
2. 工具从当前 Run 的不可变策略和 RunAsset 快照解析目标，精确校验 origin、路径规则和工作归属。
3. 当前资产登记权限与运行允许的上界分开：来源有效且通过策略检查的新页面，才能加入本 Run 的 RunAsset 并被后续工作领取。
4. fixture 与用户靶场使用可区分的 namespace，不能继续把真实靶场标记为 local-fixture-v1；身份仍包含方法与规范化 URL。
5. 响应解析依赖实际 Content-Type 与正文，不能套用 fixture 中预设标题、类型和版本字段。
6. MockProvider 根据运行时真实资产与结果生成下一步工具请求，不根据首页检查清单预填资产，也不固定生成 Home/Health 两项工作。

原有样本和 fixture 精确模式仍可测试；修改不得将历史 Run 的目标重写成新靶场。关键来源、证据和停止规则沿用第六阶段主文档。

## 4. 实际演示的验收方式

创建“启岳靶场链接发现”任务，种子仅为 `http://192.168.77.88:7780/`。启动后按本次实际响应发现和读取页面，界面显示从哪次响应发现了哪个端点。

首页若保持本次检查时的内容，应能从首页证据解析出上面 9 个新端点；是否读取成功，以各自实际调用结果为准。靶场内容可能变化，因此不能把检查清单当永久断言或预定成功结果。

对每个新资产，能打开来源首页或子页面的 ToolCall。去重、跨 origin 拒绝、错误来源、循环链接、移除链接、正文错误与停止场景继续用隔离本地测试服务验证；不要求修改靶场实现这些故障。

交付要区分：本地自动化测试通过、现有靶场实际 HTTP 验证通过、真实模型验证通过。三者分别说明；用 Mock 驱动工具时明确标注，不能称为真实模型自主探索。

## 5. 交给实现 Agent

在当前第六阶段实现上，按本补充说明接入上述现有靶场作为演示目标。无需启动新的 fixture 做演示。先运行并修复第五阶段回归场景，再解除地址和固定路径耦合，按 Run 策略控制发现与请求。

保留已有未提交修改，不回退其他功能。完成迁移、任务表单中的种子与策略输入、链接发现、动态派工、来源追溯与必要测试。实际靶场验证只读取该精确 origin 的页面，遵守页面数、深度、并发和请求间隔限制。记录实际页面与请求结果，不能以人工首页清单代替程序发现。
