# 新增能力与项目现状（2026-10-23）

## 核对范围与结论

基于本地最新提交 `9d1d027`，整理本轮对话涉及的新增功能，重点覆盖预算/血缘纠偏计划之后的实现与后续修复。核对了 Git 历史、相关源码、运行中 API、数据库只读结果和真实前端页面。

本轮不仅新增界面：版本化执行策略、持久化任务起点、MCP 扩展、API 侦察、技能读取和共享探索上下文均已有实现。运行服务已经加载新预算策略与探索图迁移；但最近两次实际任务仍因 provider_error 失败，不能宣称已完成稳定的自主探索闭环。

后续排查已确认：这些失败里包含被误报为 provider_error 的本地压缩故障。本地代码已修复短会话压缩、预载态势大小及取消误报，并通过历史离线回放和相关测试；容器尚需重建加载。见 [上下文压缩与停止误报修复](上下文压缩与停止误报修复-2026-10-23.md)。下文的现场状态保留为修复前核对快照。

梳理开始时工作区干净，位于 main，本地与 origin/main 引用一致。本文是本次新增整理文件；没有修改业务代码、重启服务、恢复任务或向测试目标发请求。

## 1. 预算与恢复机制

新增 `execution_input.execution_policy`，版本 `agent_limits.v1`。新探索 Run 在创建时冻结策略，budget 是兼容投影；旧 Run 没有新版本时仍按原预算解释。

运行中的 `/api/runtime/defaults` 已确认：

| 项目 | 新探索默认 |
| --- | --- |
| Worker 池 | 3，仍允许 1–8 |
| 任务总时长 | 不限 |
| 模型/工具总次数 | 默认不设硬上限 |
| Planner 总轮数、方向总数 | 默认不设硬上限 |
| Worker 单轮探索时长 | 1200 秒（20 分钟） |
| Worker MaxTurns | 默认不限 |
| 独立收尾 | 默认 10 轮 |
| Main | 默认不再受整个 Run 累计 8 次限制 |

专家/任务明确配置的正数限制仍生效。0 的新语义只适用于新版本；旧快照、已用量、Epoch、幂等和授权账本保留。单次请求超时、共享模型并发、网络节流等保护继续存在。

局部耗尽后先收尾写回，再交给 Planner 判断；不是自动无条件续租。无上限维度显示“无需追加”，有界维度仍能显式追加授权。没有把所有维度的统计统一成费用总账。

代码入口：`backend/internal/model/execution_policy.go`、`config/exploration.go`、`orchestration/budget.go`、`controlplane/main.go`。

## 2. 真实探索图与历史回填

补齐了此前漏掉的 ARTEX 起点机制：

```text
任务起点 ──spawns──────→ 目标
任务起点 ──derived_from→ 没有显式来源的初始方向
来源事实/发现 ─────────→ 后续方向
实际工作方向 ──yields──→ 事实/发现
有效证据 ──proves──────→ 对应目标
```

起点为真实的 fact/origin 节点，不是已验证的漏洞证据。有明确来源时保留真正的来源边，不把全部方向挂到第一个目标。Worker→Finding 的归属从可信执行上下文取得。

迁移 `033_exploration_lineage` 提供唯一根与历史幂等回填。现场数据库已为版本 33、dirty=false；已有旧任务也能看到起点。无效来源有诊断记录，不猜补证明或成果归属。

前端继续用 ExplorationNode ID 绘图，WorkItem/Finding ID 作为关联字段；fact/origin 显示为任务起点，proves 仍受证据、版本和失效条件过滤。

代码入口：`backend/internal/service/lineage.go`、`exploration_graph.go`、迁移 033、`frontend/src/lib/workbench/graph.ts`。

## 3. MCP 扩展与工具管理

新增 MCP 服务端配置、工具发现缓存和 Worker 装配能力，支持 stdio、HTTP、SSE。启用的远端工具按 `mcp__<server>__<tool>` 注册给 Worker。

新增“工具与 MCP 配置中心”页面，可以查看原生工具目录、添加/编辑/启停 MCP 服务、发现远端工具并查看其参数说明。后端运行镜像补充 Node 20、Playwright MCP 和 Chromium，并修正内置浏览器服务参数。

本次只读核对现场：

| 服务/目录 | 状态 |
| --- | --- |
| browser MCP | 已启用，缓存 25 个工具描述 |
| ScopeSentry MCP | 已登记但未启用，缓存 0 项；不等于已完成资产同步 |
| 原生工具目录 API | 返回 37 项；并不代表每个 Worker 都有全部权限 |
| `/tools` 页面 | 实际可打开并列出 browser，未出现 Internal Server Error |

缓存工具描述不等于每个浏览器动作、每个外部 MCP 都已验收；本次未主动连接外部 MCP 或运行浏览器探测任务。

代码入口：`backend/internal/mcp/`、`handler/mcp.go`、迁移 032、`frontend/src/app/tools/page.tsx`。

## 4. API 侦察与技能读取

新增 `extract_api_endpoints`，从已有可信 HTTP 响应中的 HTML 脚本、JavaScript、JSON/OpenAPI 材料提取接口路径与方法，并登记范围内资产。不再只有 HTML 超链接发现。

新增 `list_skills` / `read_skill`，供 Agent 按需读取项目中的领域指引。当前有三个：

- api-recon：API 侦察与接口定位。
- finding-verification：区分线索、事实与可验证发现。
- playwright-cli：浏览器交互指引。

新增/扩充 explore、api_recon、active_probe、browser 等能力 profile，并接入共享流量查询与 HTTP 详情读取。具体可用能力仍由 Run 冻结的 profile 和网络策略决定，技能文档本身不会增加执行权限。

## 5. 探索策略与发现分类纠偏

默认探索不再强制执行安全头配置审计，`run_security_check` 从默认开放探索能力移出；明确选择配置审查能力时仍可使用旧流程。

响应头缺失、版本指纹、通用错误页等默认按事实处理，不再直接当成已验证漏洞。漏洞上报强化 source_kind、验证状态、复现步骤和基线/证明/验证流量角色；报告区分实证发现与待验证候选。

新工作台任务默认采用“主动验证”网络模式，允许同源 GET/HEAD/OPTIONS/POST/PUT/PATCH/DELETE，支持登录、表单和 API 验证；高级设置可切回 GET/HEAD 只读。旧 Task/Run 的 readonly 策略不会因此被回写。

中文提示词和工具参数说明也已补充，目标、方向、事实、发现尽量使用简体中文，URL、方法等技术值保留原样。

主要对应提交 `7dc0873`。路线选择、同根因合并等仍主要由模型提示词推动，尚不是通用语义去重或漏洞自动证明器。

## 6. 减少成果遗忘与重复探索

最新提交 `9d1d027` 增加了规划上下文：

- GraphOverview 带最近结束方向、真实输出和结束原因、近期发现及验证/审核状态。
- 初次 Planner、后续 Planner、Worker 启动与恢复可以读取共享态势，减少新会话忘记已做工作。
- 当前 Epoch 的每源站请求/页面用量、阻断标志、可用 profile、重复工具错误和原调用 ID进入上下文。
- 提示词要求重复复访有新的假设或前提；遇到请求/页面上限后复用已存材料，不能靠换 key、换资产类型或等待来绕过。

同时修复 URL 级请求的证据绑定：已授权的新 URL 捕获成功后，登记/关联实际端点并把 receipt 绑定到资产，使后续观察与事实能正常引用。参数变体复用端点身份，不额外发请求；保留来源、范围、Epoch 和当前 Attempt 校验。

这些改动有本地替身和独立数据库回归记录，但尚未证明真实模型从此绝不重复，也没有修复上游模型服务故障。

代码入口：`service/planner_context.go`、`service/exploration.go`、`netcap/captured_asset.go`、`tools/http_request.go`、`orchestration/prompts.go`。
