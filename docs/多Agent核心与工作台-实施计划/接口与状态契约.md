# 跨 Agent 接口与状态契约（已冻结）

日期：2026-10-22。行为以本文和 `backend/internal/contract` 为准。Go 类型、错误码、命令名和 `workbench.v1` 字段已冻结；变更必须通知所有消费者，不得私下另造一版。未接线的端口返回 `not_implemented`，不能当成成功实现。

共同合同 commit 与工作树见同目录 `协调状态.md`。

## 1. 共用执行身份

任何执行、控制、证据或 Job 都要具备：

```text
ExecutionScope
  run_id, epoch_number
  role = mainagent | planner | worker | verifier
  work_item_id?, attempt_id?, session_id
  command_id? / source_tool_call_id? / job_id?
```

Worker 工具必须有 WorkItem/Attempt；Main/Planner 不伪造 Worker ID。Session 是执行记录；同 WorkItem 的对话可以跨 Attempt 恢复，不能把稳定对话 ID 当作当前执行资格。旧 call_id 的唯一性是 Session 内，不要求不同 Session 的上游 call_id 全局唯一。

原生 Provider reasoning/output 仅内部持久化，不发给浏览器或其它角色。所有 DTO 的凭据只有 alias/reference，不含实际 token、cookie、Authorization、模型密钥。

## 2. 运行时端口（Go 接口由 0 冻结，模块不得相互 import Handler）

| 端口 | 生产者 | 消费者 | 语义 |
| --- | --- | --- | --- |
| RuntimeResolver.Resolve(ctx, scope, profile) | 2 | 1、5、verifier | 返回角色 Provider、ModelOpts、限流/恢复策略、非敏感快照；旧配置默认回退 |
| ModelCallPolicy / limiter | 2 | SessionRunner（1/2 联调） | 等待可取消；每次真实请求都走共享 gate 和持久调用记录；Provider 不暗自重试 |
| ExecutionController.Apply(ctx, principal, command) | 5 | REST、Planner、Main Agent | 统一状态、授权、版本/幂等、Manager 取消/唤醒 |
| ToolsetFactory.Assemble(scope, profile) | 0 接线，各模块供工厂 | Engine、Main Agent、verifier | 角色授权与场景能力；初始/后续 Planner 不能装出不同控制工具 |
| TargetTransport / CaptureGateway | 3 | http_request、旧 get_endpoint、4 的受控代理 | 真实请求/响应、范围、TLS、凭据引用、来源凭据 |
| JobExecutor.Run/Cancel/Inspect | 4 | 命令工具、Manager/Controller | 固定镜像/环境，Attempt/Job 级隔离、进程树清理、结果/产物 |
| WorkbenchQuery.Snapshot / MainConversation | 5 | 6、7 | 小体积当前态势 + 分页会话/事件/证据引用 |

接口使用 context、UUID 和 typed errors；不把 UI 文案当状态枚举，不把任意 map 随意往下传。所有跨模块依赖通过构造注入；不创建第二个全局 Manager，不用包级可变 conversation。

## 3. 并发与模型配置快照

新 Run 的用户输入仍使用 `budget.max_parallel_workers`，范围 1–8，默认新探索任务 3；旧快照缺失字段保留旧默认 1。UI 不再通过 executorType=dual 切换执行器。

对外读视图提供：

```json
{
  "worker_capacity": {"requested":4,"effective":4,"active":2,"queued":3},
  "model_capacity": {"limit":2,"in_flight":2,"queued":1}
}
```

如 server 上限不允许请求值，返回 400/concurrency_out_of_range；不能快照 4 而实际强制 1。origin HTTP 请求节流可以小于 Worker 并发，并显示等待原因；它不等于 Worker 池被降为 1。

角色运行配置建议放在 `execution_input.agents`，例如：

```json
{
  "agents": {
    "mainagent":{"runtime_profile":"default","model":"configured-model"},
    "planner":{"runtime_profile":"default","model":"configured-model"},
    "worker":{"runtime_profile":"default","model":"configured-model"},
    "verifier":{"runtime_profile":"default","model":"configured-model"}
  }
}
```

`runtime_profile` 引用服务器已配置 Provider/凭据别名，不是用户或模型提供任意执行代码。保留 agent_config，旧配置作为所有角色默认。运行中不悄悄修改模型快照；变更在明确的新执行配置版本/Epoch 生效并记录，细节由 0 冻结。

## 4. 状态与错误影响范围

| 情况 | 默认范围 | 行为 |
| --- | --- | --- |
| Worker 局部模型/工具/时间额度 | Attempt | settlement→exhausted；其它方向继续，Planner 可有界继续 |
| Worker 工具错误、refusal、输出截断或坏模型响应 | Attempt/Session | 保留原失败；有界恢复策略，最终 failed 或 exhausted；不强行结束其他 Worker |
| Planner 429/5xx/暂时超时 | 规划轮 | 有界退避，不开第二个 Planner，不阻塞已有 Worker 的有效工具/派工 |
| Planner 连续坏协议/不可用 | Run 协调器 | 到阈值后明确 needs_input/失败，保留过程并有界关闭子执行；不能无限保持 running |
| 硬总预算、用户 Stop、全局 deadline | Run/Epoch | 停止新准入，保存进度、清理和明确终态；不是全员工具失败 |
| 持久化不可信、有效 Epoch 丢失 | Run/Epoch | 停止可产生副作用的执行，保留诊断，禁止错误地继续写成果 |
| 单方向 Kill | WorkItem 当前 Attempt | 取消该方向及 Job，不影响其它方向；后续父 Run 恢复也不自动复活 |
| 上游模型限流等待 | 请求排队 | 可取消、有等待态；不是 Worker failed，不占用一条假成功调用 |

错误信封至少为：

```json
{
  "error": {
    "code":"invalid_model_output",
    "scope":"session",
    "message":"模型返回不完整工具参数，本轮未执行这些调用",
    "retryable":true,
    "source_id":"<model_call_uuid>",
    "suggested_action":"retry_direction"
  }
}
```

HTTP 400 输入、403 范围/权限、404 对象、409 状态/Epoch/幂等冲突、413 内容超限、429 服务限流、503 执行服务不可用、500 内部故障。错误响应不得原样泄漏上游凭据/请求头/SQL。自然语言目标不达成不是 HTTP 500。

## 5. 控制命令

统一命令入口建议 `POST /api/runs/{runID}/commands`，旧控制 URL 仍兼容但调用相同 Controller。请求 header `Idempotency-Key` 必需；Run/Epoch/WorkItem 预期值用于防迟到：

```json
{
  "type":"steer_work",
  "expected_epoch":2,
  "work_item_id":"<uuid>",
  "expected_attempt_id":"<uuid>",
  "payload":{"instruction":"先查看已保存的响应，停止重复读取同一页面"}
}
```

返回 command_id、status=accepted/applied/rejected、type、实际 epoch、关联工作/Attempt、结果与错误。accepted 是已持久接收，不等于 Worker 已经读到；投递确认单列。重复相同键/内容返回原结果，并在响应副本上带 `replayed=true`（不写入已存结果）。同键不同内容 409。Planner 工具的默认幂等键包含当前 session，同一轮重试不重复生效，下一轮必须重新经过状态机。

最小命令集合：hint、add_intent、steer_work、kill_work、continue_work、retry_work、pause_run、resume_run、stop_run、start_epoch、grant_budget。已有工具名 continue_work_item/retry_work_item 可保留，映射同一服务。

principal/role 在服务器调用上下文建立，不能通过 JSON 自报 role=human 获得授权。Planner 可管理方向、读证据，不可 grant_budget/start_epoch/扩范围；Main Agent 对用户明确要求的授权内操作可执行，对总预算/范围变更走结构化用户授权通道。Controller 不在数据库锁内调用模型或等待进程退出。

## 6. HTTP/HTTPS 与可信来源

工具 `http_request` 的最小输入：asset_id 或 scope 内规范 URL、method、query、headers（敏感值用引用）、body_json/body_text/form 三选一、credential_ref?/session_ref?、timeout_seconds。服务器从冻结策略校验，而非信任模型提供的 allow=true。

返回最小结构：

```json
{
  "request_id":"<uuid>",
  "receipt_id":"<uuid>",
  "asset_id":"<uuid>",
  "method":"POST",
  "url":"<redacted scoped URL>",
  "status_code":200,
  "response_preview":"...",
  "request_artifact_id":"<uuid>",
  "response_artifact_id":"<uuid>",
  "truncated":false
}
```

receipt 由服务器网关生成，绑定 ExecutionScope、实际请求/响应及哈希、认证引用版本、来源工具/Job；模型不能自己组 JSON 声称拥有 receipt。认证值由服务器/网关注入目标请求，UI/模型只见别名。UI 按权限看脱敏内容，原始敏感载荷访问不能藏在普通事件广播里。

HTTPS CONNECT 透传只能看到隧道元数据，不等于已捕获请求/响应正文。若为命令链提供 HTTPS 正文来源，网关须实现显式受信 CA 的 TLS 解密捕获，执行镜像正确安装该 CA；私钥不进入执行容器，不能用全局关闭证书校验代替。直接 http_request 路径的 TLS/证据同样必须真实可核验。

每跳重定向重新校验 origin/path/方法；跨来源时不转发认证。TLS 默认验证，fixture 使用专用 CA。DNS/连接地址与范围校验一致，不能因支持 HTTPS 放开 SSRF 或命中 API/数据库管理地址；明确授权的本地测试端口应可用。

report_finding 的 empirical 入口接受旧 get_endpoint 来源或新增可信 HTTP receipt，不能仅凭普通工具 success/命令输出判定实测。Agent 3 修改 verification 解析并写反例。旧 HTTP 条件复测继续正常；无法安全自动重放的认证/有副作用请求可返回 inconclusive 和清楚原因，禁止盲目重放，也不以异常登录页推断 fixed。复杂通用漏洞裁决暂缓。

## 7. 执行 Job 和工作空间

新增工具最少 run_command、write_file、read_file、inspect_command。命令按固定 shell/argv 协议在允许镜像的专属容器执行，不在 API/宿主机执行。它可以用来生成/运行分析脚本并经受控网关请求目标。

```json
{
  "job_id":"<uuid>",
  "state":"finished",
  "exit_code":0,
  "stdout_artifact_id":"<uuid>",
  "stderr_artifact_id":"<uuid>",
  "traffic_refs":["<receipt_uuid>"],
  "execution_receipt_id":"<uuid>"
}
```

一期 run_command 为有界同步命令；明确声明 timeout_seconds，受 Attempt/Run 剩余时长夹逼，合理工具超时单独配置，不继续沿用所有工具 5 秒的隐式上限。后台/未知结果由 inspect_command 查询，不自动重放。超时或取消后有独立清理窗口，记录 killed/interrupted/outcome_unknown，不伪造 exit_code=0。

工作目录属于稳定 WorkItem，可在新 Attempt 以受控产物投影恢复；执行容器/进程属于新 Attempt，不能复活旧进程。每个 Job/Attempt 不得访问其它方向文件；不能仅在同一个任意 Shell 中拼目录名就宣称隔离。

完整 stdout/stderr、脚本与产物复用 ArtifactService；保留现有一条 source_tool_call 的规范完整输出约束，额外子产物通过 Job-artifact 关系引用，不粗暴删除既有唯一索引。agent_tool_calls.status=success 表示工具机制成功返回，exit_code 和业务发现另列。

## 8. Main Agent API

建议：

- `POST /api/runs/{id}/main/messages`：幂等提交用户回合，body={message,expected_epoch}，202 返回 message_id/turn_id/session_id。
- `GET /api/runs/{id}/main/messages?after_seq=&limit=`：分页读取对话、真实工具动作引用、turn 状态；不返回内部 Provider 载荷。
- 同 Run 主会话回合串行；不同 Run 独立；页面断线后可按 cursor 找回已提交回合。
- Main 的模型调用可取消、留痕且有单列预算；涉及扫描动作仍受 Run 授权和池容量，不借聊天绕过全局约束。
- completed Run 的状态查询可运行主对话，不重启扫描。真正继续需明确恢复语义与 expected_epoch，再调统一 Controller；没有用户恢复指令时不得重启。

主对话 action 消息必须引用真实 command_id/model_call_id/tool_call_id/work_item_id，不从自然语言猜一个成功动作给 UI。

## 9. 工作台读视图

`GET /api/runs/{id}/workbench?after_event_seq=&limit=` 建议返回：

```json
{
  "schema_version":"workbench.v1",
  "snapshot_at":"<UTC ISO timestamp>",
  "run":{"id":"<uuid>","status":"running","epoch_number":2},
  "worker_capacity":{"requested":4,"effective":4,"active":2,"queued":3},
  "model_capacity":{"limit":2,"in_flight":2,"queued":1},
  "budget":{},
  "goals":[],
  "planner":{"status":"waiting","reason":"等待当前方向写回","session_id":"<uuid>"},
  "directions":[],
  "main_conversation":{"last_seq":12,"active_turn_id":null},
  "events":[],
  "last_event_seq":123,
  "has_more_events":false
}
```

direction 至少包含 stable WorkItem ID、目标/来源引用、状态、当前 Attempt/Session、最新真实步骤、进展时间、局部额度、错误及允许控制动作。细节和大正文按需读旧 trace/artifact API，读视图不复制所有原始消息。

last_event_seq 只用于事件分页，不能假设它涵盖所有工具/状态变更然后跳过快照刷新。聚合用一致性快照/明确定义的读取语义，避免同一响应中 Run completed 但当前 Epoch 仍 running。若做增量 revision，必须覆盖所有相关写入；否则一期直接每 1–2 秒获取小快照即可。

## 11. 冻结决定（Agent 0，M0）

实现包：`agent-workbench/backend/internal/contract`。它只依赖标准库和 `github.com/google/uuid`，不导入 handler、service、orchestration、tools、provider。`cmd/server` 是唯一生产装配根。本提交不挂载新路由，也不把 `Unimplemented*` 接进现有 Engine。

| 端口 | 包内类型 | 依赖方向 |
| --- | --- | --- |
| 模型解析 | `RuntimeResolver` | Agent 2 实现；SessionRunner / Engine / Main 只依赖接口。返回的 `ModelCaller` 由 provider 适配，合同不导入 provider |
| 模型准入 | `ModelCallPolicy`、`CallOnce` | 每次真实调用都是 Acquire、一次 Call、Complete。重试是新的 Acquire。Provider 内不得循环重试 |
| 工具准入 | `ToolExecutionPolicy` | 工具执行前调用。策略不导入 tools，tools 不导入 service |
| 工具装配 | `ToolsetFactory` | 各模块提供绑定，0 在启动工厂统一装配。初始/后续 Planner 的控制工具集合必须相同 |
| 控制 | `ExecutionController.Apply` | REST、Planner、Main Agent 共用。principal 由服务器调用路径建立，JSON 不能自报 role |
| 资源撤销 | `ResourceRevoker` | Controller 与 Manager 调用。HTTP、Job、模型等待各自实现，0 组合，不建第二个 Manager |
| 捕获 | `TargetTransport`、`CaptureGateway` | Agent 3 实现。receipt 只能由网关生成；`RejectModelMintedReceipt` 拒绝模型自组 JSON |
| Job | `JobExecutor` | Agent 4 实现，构造时注入 `CaptureGateway`。只设置 `HTTP_PROXY` 不算实现该接口 |
| 工作台 | `WorkbenchQuery` 与 `workbench.v1` | Agent 5 生产，Agent 6 只消费。fixture 在 `backend/internal/contract/testdata/` |

已冻结且可直接调用的规则，不是待实现的运行时：

- `ParseAgentsConfig`：`execution_input` 没有 `agents` 时沿用旧的单一 `agent_config`，不报错。字段存在但别名非法时拒绝，不部分生效。
- `CommandRequestHash` / `MainMessageRequestHash`：对解码后的结构做 SHA-256。同键同摘要返回原结果；同键不同摘要返回 409。不要另写一套摘要。
- `AcceptWorkerCount` / `DiscoveryMustHonorRequestedWorkers`：请求 4 得到 4；超过服务端上限返回 `concurrency_out_of_range`，不得改成 1。旧快照缺字段仍是 1；新探索任务缺字段默认 3。
- `NextConfigRevision`：运行中的 Epoch 不改模型快照，变更落到更新的 Epoch。
- `CommandAllowed`：Planner 不可 `grant_budget`、`start_epoch`、暂停/恢复/停止。Main Agent 变更必须带服务器设置的 `ExplicitUserCommand`。`grant_budget` 只允许 human 的结构化授权。
- `RejectIncompleteToolCalls`：不完整参数或 status 不可执行，不补全 JSON。
- `HTTPReceipt.EmpiricalSource`：只有 `direct` 与 `tls_intercept` 可作为实测来源。`connect_metadata` 不是响应正文。
- `JobView.Validate`：`exit_code` 只在 `finished` 时出现。killed / interrupted / outcome_unknown 不得伪造 0。
- `ExecutionPorts.ProductionReady`：任一端口为空或为 `Unimplemented*` 时失败。生产不得静默改用 mock。

路由常量：`POST /api/runs/{runID}/commands`、`GET /api/runs/{runID}/workbench`、`POST/GET /api/runs/{runID}/main/messages`。幂等头为 `Idempotency-Key`。新路由使用 `Envelope`。旧路由仍返回 `{"error":"<string>"}`，本提交不改旧响应。

命令名：`hint`、`add_intent`、`steer_work`、`kill_work`、`continue_work`、`retry_work`、`pause_run`、`resume_run`、`stop_run`、`start_epoch`、`grant_budget`。旧工具名 `continue_work_item` / `retry_work_item` 映射到 `continue_work` / `retry_work`，不另建服务。

迁移号 026–030 只保留在常量里。本提交没有新增 SQL。空文件会被合同测试拒绝。001–025 不重写。

最小 JSON 示例：

- `testdata/workbench.v1.json`
- `testdata/command.steer_work.json`
- `testdata/error.invalid_model_output.json`
- `testdata/http_receipt.json`
- `testdata/job.finished.json`
- `testdata/agents.config.json`

`origin_pacing` 是工作台可选字段。它表示源站网络等待，不能通过降低 `worker_capacity.effective` 来表达。

预算模板 `SuggestedExplorationTemplate` 与 `SuggestedQuickTemplate` 是显式初始建议，不自动改写已有 `DefaultBudgetConfig`。Agent 1/2 若要改数字，先拿实测通知 0。
