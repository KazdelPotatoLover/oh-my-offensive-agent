## 能得出的结论

领取 SQL 是 `ORDER BY wi.created_at ASC LIMIT 1`，没有第二排序键。同一次 `SubmitPlan` 写入的两条方向可能具有相同的 `created_at`，因此“数组第 0 项一定先被领取”不是稳定断言。这是旧测试在全包运行中的顺序问题。它不证明用户看到的双 Worker 失败来自数据竞争，也不能用来宣布 N Worker 已修复或已损坏。

`handler/run.go` 在 discovery 分支仍把 `MaxParallelWorkers` 写成 1。该行本轮未改。
