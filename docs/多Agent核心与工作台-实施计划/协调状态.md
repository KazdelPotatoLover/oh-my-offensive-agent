## ARTEX 对照与有意差异

已读参考仓库，未改 ARTEX。

- `server/engine.go` 的 `plannerLoop` 是单规划循环，边沿与心跳触发，防抖后开新一轮。Worker 领取不在规划模型调用内。
- `agent/worker.go` 的 `execute` 按意图保留 transcript，并为该次执行准备目录、代理环境和工具输出目录。恢复对话不等于恢复进程。
- `PlannerTools` 含 `kill_work` / `steer_work`，通过引擎回调生效，不由模型直接写取消状态。
- `MainAgent.Chat` 每轮新建 Session 并恢复主会话 transcript，不启动规划循环。
- `AugmentTools` 按角色键在基础工具上追加可见工具。
- `captureRunSession` 记录执行步骤。它不是本工程的 HTTP receipt。
- `clampMaxDuration` 用任务截止时间夹逼单次运行时长。

有意差异：PostgreSQL 仍是状态权威；保留 execution epoch、总硬额度和授权账本。本工程新增 Worker 执行受 N 上限约束。命令在执行容器中运行，不能把 ARTEX 的宿主机 Bash 与 `HTTP_PROXY` 当成范围隔离。来源 verified 仍不等于自然语言命题自动成立。
