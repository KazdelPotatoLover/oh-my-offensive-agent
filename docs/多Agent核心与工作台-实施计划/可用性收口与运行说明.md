## 修复内容

1. Planner 保留独立 Dispatcher；默认内部模型槽位给 Planner 留出空间，不再默认等于 Worker 数。显式上游限流仍有效。Worker 完成、事实和人工信号唤醒 Planner；无事件时按 ARTEX 十分钟心跳巡检。
2. 初轮 Planner 不再把自己执行期间产生的 Worker 变化一并当作已读；Nudge 真正标记需要重新评估。
3. 任务会话、Main 和独立复测复用一个服务实例的模型限流池；工作台显示同一个池的实际容量。恢复请求仍由会话循环记账并有界重试。
4. Main 使用当前 Run 保存的模型路由及本地凭据，恢复已完成的对话文本；旧工具调用不会随历史文本重新执行。
5. 工作台创建默认复用服务器模型，不再提交虚构别名或空能力集。新任务显式保存 HTTP(S) 只读网络授权；可选启用隔离 Python/curl 和工作区文件工具。旧快照不扩大权限。
6. 捕获网关向命令代理返回完整、有界的原始响应，不再把缩短的预览当正文。
7. `http_request` 的可信收据接入观察与事实校验；URL 精确匹配已有且分配给当前方向的资产时，保留该资产关联。复制到另一调用的收据仍不可信。
8. 通用产物工具能读取同 Run 的 HTTP 捕获正文；保留跨 Run 校验和敏感内容脱敏。
9. 补齐执行代理的 Compose 参数、稳定 Broker 状态卷及一致的宿主工作区路径，增加本地启动入口。
10. 修正验收请求：停止必须带 epoch 和幂等键；恢复和上游限流显式配置；监督测试用事件触发，释放 Worker 槽位后才检查继续派工。没有放宽证据或范围校验。

Worker 与 Planner 提示词同时减少重复查能力、查自身 trace 和错误证明 ID；工具列表排序固定。没有新增一套固定扫描流水线。
