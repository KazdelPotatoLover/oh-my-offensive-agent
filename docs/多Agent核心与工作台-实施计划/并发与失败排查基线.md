## 已确认事实

1. UI `frontend/src/app/tasks/[taskId]/page.tsx:handleStartRun` 构造 budget.max_parallel_workers，现有界面只给 1/2 两个选项。
2. `service/run.go:Create` 接受 req.Budget.MaxParallelWorkers，快照保存原预算。
3. `handler/run.go:startRunExecutor` 在 isDiscovery 时再次覆盖 budget.MaxParallelWorkers=1；即使请求 2/4，实际 Engine 也可能是 1。这是配置/生效语义不一致，静态代码可确认。
4. `orchestration.NewEngine` 从最终 budget 读取 maxWorkers，<=0 时默认 1；现有池、共享额度和 Worker 独立 Session 不能据此直接视为坏掉。
5. 开发库只读聚合：33 个 Run；24 个 max_parallel_workers=1，9 个字段缺失，无显式 2/4。不能宣称已获得“双 Worker 竞争”的生产复现。
6. 当前 backend/frontend 容器约 36 分钟前重建启动（检查当时），所以排查仍需记录运行镜像与源码是否一致，不能只看 git。
