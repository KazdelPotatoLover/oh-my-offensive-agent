## 参考机制、现状与适配

参考相邻 ARTEX 的 `agent/tools.go:graphOverviewData`、`agent/planner.go:renderGraphOverview/renderTriggers` 与 `agent/worker.go:renderWorkerGraphOverview`：Planner 每轮新会话读取预取态势、最近结束意图和工作结论；Worker 了解共享发现以避免重复，但只推进自己的意图。ARTEX 的提示词负责比较方向，并非数据库自动理解语义。

本工程原本提供进行中方向及结束计数，缺少结束方向正文/结论和已有发现摘要；新 Worker 也缺少共享态势。URL 级 HTTP 捕获虽然存在，但未预先分配端点时无法进入依赖资产绑定的证据链。

本次调整：

1. `GraphOverview` 增加最近 20 个结束方向及结论/结束原因、最近 20 个发现和验证/审核状态、事实状态/版本。删除的方向不进入摘要。
2. 注入当前 epoch 的每源站请求/页面用量、硬阻断标志、授权 profile 名称、最近失败聚合和原始调用 ID。初次规划、后续规划及 Worker 启动/恢复均获得态势；细节仍按需读取。
3. 提示词要求复访说明材料性新假设或前提变化；额度拒绝后复用已有材料，禁止用等待、改 key、改资产类型反复复测。无可执行路径时按 partial/blocked 解释缺口，不伪造目标证明。
4. 已授权的新 URL 捕获完成后，在事务中登记/关联实际端点并绑定 receipt。查询参数变体复用端点身份，不额外发请求；只接受当前 Worker/Attempt 的真实待完成调用和网关回执。绑定失败仍保留捕获并返回明确警告。

每源站硬额度、epoch 隔离、数据库持久化摘要以及回执资产绑定属于本工程适配。此改动没有实现通用语义去重，也不保证模型绝不重复；方向选择仍受模型策略影响。没有增加额度或放宽证据来源与目标证明条件。
