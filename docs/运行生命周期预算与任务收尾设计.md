# 运行生命周期、预算与任务收尾

## 范围和责任

本次改造统一现有 Engine、单 Agent 和模拟执行器的终止流程，不增加新的执行框架。HTTP 接口、预算快照与历史证据的格式保持兼容。参考 ARTEX 的 settling/drain、具名取消与条件更新，但本项目保持单进程执行与重启后中断、不自动重放的语义。

| 组件 | 唯一责任 |
| --- | --- |
| Engine / AgentRunner | 执行会话、协调停止和结果保存 |
| BudgetManager | 同一 Run 的模型及工具额度原子申请 |
| SessionRunner | 请求前申请额度，持久化调用和消息，拒绝取消后的工具请求 |
| RunService.FinalizeRunWrapup | 锁定父 Run，决定终态，原子清理活动子记录 |
| Manager | 注册唯一执行器，传递用户停止或进程关闭原因，等待执行器退出 |
| RunService.RecoverActiveRuns | 启动时恢复残留活动 Run；成功完成后服务器才开始接受请求 |
| 数据库 | 条件更新、唯一约束与短事务；事务不跨模型请求或网络工具 |

## 状态及写入顺序

Run 保留已有 `queued/running/stopping/completed/failed/stopped/interrupted` 状态。收尾阶段通过 BudgetManager 的 admission barrier 表达，不额外引入 API 枚举；`stopping` 继续专门表示已持久化的用户停止意图。

正常执行：`queued → running → completed/failed`。
用户停止或运行超时：经 `stopping → stopped`。
进程关闭或启动恢复：`queued/running → interrupted`；已经 `stopping` 的 Run 仍收敛为用户停止。

收尾顺序：

1. 原子关闭探索调用和新工作准入。
2. 向 Worker context 传递具体结束原因。
3. 最多等待 5 秒让 Worker 退出、完成最后的数据库写入。
4. 生成模型总结或程序化部分结果。
5. 使用独立且最多 10 秒的清理 context，调用统一收尾事务。

终态事务先锁父 Run，再清理子表。领取工作、创建会话/调用/消息、写观察也先锁父 Run，从而不与终态清理交错产生新的活动记录。已开始的工具可在等待期间保存结果；父 Run 最终结束后，业务写入和新活动记录被拒绝。

Go 无法强制杀死忽略 context 的 goroutine。有界等待保证 Run 可以收敛；数据库终态保护保证该 goroutine 以后返回时不能复活状态或执行它新请求的工具。外部已经发生的操作无法回滚，因此工具本身仍必须尊重 context。

## 必须保持的约束

- 一个 Run 在 Manager 中同时最多注册一个执行器；一个 WorkItem 通过父行锁和条件领取获得一个当前 Attempt。
- 额度在模型/工具入口申请，不依赖调度器轮询计数。失败、取消和申请后持久化失败都不退回消耗额度，避免不确定请求被重复发出。
- Worker 直到完成最终数据库写入才释放活动计数。最后一个合法模型请求返回后，调度器也不会提前把仍在保存结果的 Worker 终止。
- 收尾后不领取工作，不接受新的探索模型或工具调用。
- 终态 Run 不得遗留活动的 WorkItem、Attempt、Session、PlannerRound、ModelCall 或 ToolCall。
- 幂等收尾保留已完成记录、已有最终输出与第一位终态写入者的原因；父 Run 已终态也可以补齐未完成的子记录。
- 模型和工具调用记录的结果更新只作用于活动状态，迟到结果不能覆盖 `interrupted`。
- 收尾事务失败返回错误并记录日志，不当作成功。进程管理器对取消后仍活动的 Run 补偿；重启恢复可再次处理未终止 Run。

## 预算语义

BudgetManager 从 Run 开始执行时计时，和执行 context 使用同一时长。未设置时沿用 120 秒默认值。

- `MaxModelCalls > 1` 时，从总额度中预留 1 次总结请求；只剩 1 次额度时不预留。
- 探索和总结合计不得超过记录的总硬上限。模型请求开始前增加 consumed/inflight，返回或调用记录创建失败后减少 inflight；consumed 不回退。
- 工具额度在工具入口按次申请，所有 Worker 与 Planner 共用一个管理器。
- 进入收尾后只允许显式标识的总结请求，总结没有可执行工具。
- 派工余量为 `max(3 秒, ToolTimeoutSeconds)`，但不超过显式配置运行时长的十分之一，以保留短运行的可执行性。
- 预算或派工余量不足时，先等待现有 Worker 保存结果。没有 Worker 在执行后进入收尾；总体 deadline 到达则立即广播取消并开始有界等待。

预算耗尽时最多使用一次预留模型调用：使用原运行 context、剩余运行时间、模型单次超时以及最多 5 秒的总结时限。不会在用户停止、进程关闭或运行截止后额外请求模型。

总结失败、模型拒绝、工具请求、额度不足或 deadline 到达时，保留程序化报告：结束原因、完成/未完成工作、资产和观察证据引用。即使模型总结成功，也附上程序化清单。模型不是持久化事实的唯一来源。

单 Agent 执行器保留单会话的本地预算，不参与多 Worker 共享额度；其终止仍走同一个服务事务。

## 原因与竞争裁决

核心原因包括 `completed`、`user_requested_stop`、`timeout`、`model_calls_exhausted`、`tool_calls_exhausted`、`internal_error`、`shutdown`。已有 `final_answer`、模拟执行完成标签与细分错误标签保留兼容。

| 结束情况 | Run | 尚活动的 Attempt / Session | 未完成 WorkItem |
| --- | --- | --- | --- |
| 完成 | completed | stopped | cancelled |
| 用户停止 / 超时 | stopped | stopped | cancelled |
| 预算耗尽 / 执行错误 | failed | failed | cancelled |
| 进程关闭 / 重启恢复 | interrupted | interrupted | failed |

PlannerRound 不支持 interrupted，进程中断时记 stopped。已有终态子记录保持不变。

竞争规则：

1. 已落库终态及原因不再被后来的结束事件覆盖。
2. 尚未终态且数据库已是 `stopping` 时，用户停止优先。
3. 收尾中检测到运行 context 已取消时，采用其具名原因；deadline 已到时不再把最终原因写成普通预算耗尽。
4. 仅发送停止意图但尚未成功持久化时，不承诺抢占已经完成的终态事务。

模拟执行器的停止标签从 `user requested stop` 统一为 `user_requested_stop`。进程关闭从误标用户停止改为 `interrupted/shutdown`；重启原因从 `server restarted` 统一为 `shutdown`。

## 启动和历史异常处理

服务器建立服务后，在开始监听前调用 `RecoverActiveRuns`，恢复阶段整体最多 30 秒。它先完整读出并关闭扫描结果，再逐个调用收尾事务；扫描或收尾出错时启动失败，不带着不确定活动状态继续服务。

- queued/running：interrupted/shutdown，保留已有结果，不重放请求。
- stopping：stopped/user_requested_stop。
- 重复恢复没有活动 Run 时不产生额外状态事件。

本次不自动改写历史终态 Run。旧的 `0b880624-0318-4990-b02a-6f8054fb74b9` 可在单独授权后调用统一收尾补齐子状态，保留其原失败原因、证据和输出，并记录修复审计。当前验收不执行该操作。

## 资产发现图

`asset_discoveries` 表示真实链接关系，允许环。`run_assets.is_seed` 固定记录初始种子，不会因为后来出现回链而丢失；`depth` 表示从任意种子出发的最短距离。

发现事务执行：

1. 验证已保存的 HTTP 证据、会话来源、范围和 Run 状态。
2. 从显式种子计算源页面的最短深度。使用有深度上限的递归 CTE，`UNION` 去重 `(asset_id, depth)`，避免枚举所有环路路径。
3. 源页面无法从种子到达时返回错误，不默认为深度 0。
4. 新资产受深度、页面数和唯一键限制；既有资产仍可登记新链接，但跳过自链接关系。
5. 新增较短路径后重新计算已发现页面的最短深度，后续发现按更新后的距离判断。
6. 查询失败立即退出事务；保留最初的数据库错误，不继续在失效事务中写入。

迁移 011 新增种子与深度字段。种子根据历史快照、原始 seeds 和无入边记录回填，能识别已有导航回链的原始种子。旧 depth 在下一次成功发现事务中刷新，不宣称迁移已重新计算所有历史图。

## 验收方式和边界

使用隔离的 PostgreSQL 测试库、fake provider、已保存的 HTML 证据和同步通道。测试涵盖最后一次合法调用、并发额度申请、总结失败、结束事件竞争、重复收尾、终态父项残留、拒绝迟到写入、启动恢复、忽略取消的模型、成环链接、多种子和较短路径。

真实靶场测试默认跳过，只有显式设置 `RUN_LIVE_TARGET_TESTS=1` 才会访问网络。此次不调用真实模型或靶场，不对开发数据库执行迁移或修复，不自动部署。

该设计面向单个后端进程。多副本执行、跨进程租约和自动重放外部副作用不在本次范围内。
