## 数据与执行流程

`inspect_http_endpoint → 已保存 HTTP 工具证据 → run_security_check → CheckResult → pending_review Finding → 报告/页面`

检查阶段不会重新抓取页面。Planner 安排注册规则或规则组，Worker 只能执行计划指定的目标与规则。检查可以跨同一 Run 的采集 Session 复用证据，但执行它的 Attempt/Session/WorkItem 必须属于当前活动工作。

模型仅选择检查和解释结果。服务端根据保存的响应重新计算状态、解释、证据快照及候选发现等级，不采信调用方自报的“通过”或“严重漏洞”。

重复检查按 Run、资产、规则版本及原始工具证据去重。没有证据时也在父 Run 行锁下去重。复用已有结果时保留原结果来源，并将结果编号写入本次检查工具输出，用于验证当前 Attempt 确实执行了检查。

## 审查发现与已修复问题

1. **检查结果缺少完整证据边界校验**：原实现仅验证资产属于 Run。现增加执行上下文、工作资产、计划规则、证据 Run/资产/工具状态与观察来源关联校验；批次校验失败整体回滚。
2. **调用方可传入任意结果和风险等级**：现根据注册检查与原始证据重新计算，不允许调用方修改规则结果或将候选发现升级为已确认漏洞。
3. **重复检查导致新 Worker 被误判失败**：原结果属于旧 Attempt，按当前 Attempt 查询会为空。现基于成功检查工具输出中的结果编号识别复用，保留原审计归属。
4. **HSTS 字符串匹配产生错误通过**：原实现仅检查是否包含 max-age。现检查正数字值及重复指令，覆盖 max-age=0、非法值、误匹配；IP 字面量不作为 HSTS 主机策略目标。依据 [RFC 6797 §6.1.1](https://www.rfc-editor.org/rfc/rfc6797.html#section-6.1.1) 与 §8.1.1；不宣称完整模拟浏览器策略处理。
5. **证据缺失被当成配置缺失**：缺少合法 URL/响应头结构时返回证据不足，不生成风险发现。
6. **检查事件错误被忽略**：事件写入错误现在返回并回滚；列表查询检查 rows.Err，空结果稳定返回数组。
7. **前端未接检查结果与发现 API**：增加检查面板、状态、候选发现、规则版本、证据快照和原始 HTTP 工具结果展开。
8. **计划允许给样本资产安排 HTTP 检查**：现在提交计划时直接拒绝类型不匹配。

同时更新新 Run 的提示词/工具契约版本为 v4/v2；不重写历史快照。
