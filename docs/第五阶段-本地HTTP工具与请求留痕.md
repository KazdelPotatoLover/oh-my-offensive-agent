# 第五阶段：本地 HTTP 工具与请求留痕

## 1. 当前检查结果

已检查第四阶段尚未提交的实现；仓库 HEAD 为 `e485498`，实际工作区包含迁移 007、资产服务、资产页面及追溯测试等修改。保留这些修改，不覆盖或回退。

复查时，后端 `go test ./... -count=1 -timeout=120s` 在独立临时数据库中通过，临时数据库已删除；前端 `tsc --noEmit --incremental false` 通过。没有验证浏览器交互和真实模型调用，也不能据此认为所有并发边界均已覆盖。

下一步把“读取代码里的样本”扩展成“读取本地应用的实际 HTTP 响应”，复用现有任务、资产、工作、观察与追溯流程。

## 2. 先理解变化

```text
之前：Worker → read_sample → 内置固定数据

现在：Worker → get_endpoint(asset_id)
               → 程序校验工作与 Run 范围
               → 请求本地演示应用
               → 保存实际请求与响应
               → 模型读取结果并登记观察
```

模型可以用 Mock 驱动，但 HTTP 工具必须真的请求本地服务。模型是否真实、工具是否真实是两件独立的事，界面要分别表明。

本阶段的验收目标：修改本地应用的返回内容，再启动一次 Run，可以在同一个资产的两次历史中看到不同的真实响应。

## 3. 先修正第四阶段的三个边界

### 3.1 空范围不能等于全部允许

当前 `IsSampleInRunScope` 在 run_assets 数量为零时返回 true，并把这种情况解释成历史数据。新 Run 的空范围、错误范围也可能得到同样结果。SubmitPlan 与观察校验中也有“有资产才检查范围”的路径。

新增明确的范围策略版本或等价标记，由服务端创建 Run 时保存。迁移前的历史数据与迁移后的新 Run 必须可以区分，不能靠关联行数量推断历史版本。

- 新执行使用明确范围；空集合表示没有可执行目标，未知 ID 或格式应返回明确输入错误。
- 不允许从“解析失败”退化成“所有目标可用”。
- 历史数据保持可查看；不能因为历史兼容就获得新的 HTTP 执行权限。
- 旧样本测试如需执行读取，应提供明确样本范围；不要统一标成 legacy 来绕过新校验。

### 3.2 停止与观察写入要有确定顺序

当前 CreateObservationWithAsset 读取 Run 状态时没有使用行锁。同一事务稍后插入观察时，停止或终态转换可能已经提交。

将“检查 Run 仍允许运行”和“写观察、写对应事件”放进持有 Run 行锁的短事务，与现有停止流程使用一致的锁顺序。若 stopping 先提交，观察必须被拒绝；若观察先提交，停止随后生效。网络请求不在该事务内。

### 3.3 显式错误 ID 不能被当成未填写

record_observation 对非空但无法解析的 asset_id 要返回参数错误，不能静默改成 nil 后自动绑定。call_id 查找继续限定当前 Session。

用必要的回归测试验证上述行为，再继续本阶段。

## 4. 本地演示应用

增加一个独立的轻量 fixture 服务，提供三个 GET 接口：`/`、`/login`、`/health`。使用与现有端口不冲突的本地端口，建议 `29090`，绑定 `127.0.0.1`。提供启动命令，并按当前 Docker Compose 的 host 网络方式接入。

这些页面返回简单 HTML 或 JSON，没有登录动作或业务修改。让 `/health` 的版本号可以通过 fixture 配置改变，便于比较两次执行。

样本服务与模型 Mock 独立：HTTP 演示可以使用 MockProvider，但必须有真实的 fixture 请求日志或计数，证明工具确实发出了请求。

## 5. 新工具与范围

新增 `get_endpoint`，模型只传 asset_id。工具在后端通过当前 Run 的不可变资产快照解析 URL；不接受模型传任意 URL、HTTP 方法、请求头或正文。

第一版只允许：

- `http` 协议。
- 明确配置的 `127.0.0.1` 与 fixture 端口。
- 三个固定路径和 GET 方法，无查询参数。
- 资产同时属于当前 RunAsset 与当前 WorkItemAsset。

未关联资产的工作不能调用这个工具。汇总工作仍只读取已有观察与证据，不能获得 get_endpoint 权限。Planner 只负责规划，不直接请求目标。

本阶段使用数字 IP 避免域名解析变化；禁用环境代理，不自动跟随重定向，也不自动重试。3xx 本身作为收到的 HTTP 响应记录，不能额外请求 Location。任何目标扩展都留到后续明确设计，不增加通用爬虫或 Shell。

## 6. HTTP 资产身份

增加 `http_endpoint` 类型，namespace 可用 `local-fixture-v1`，稳定身份至少包含 HTTP 方法和规范化 URL。

本阶段规范化只覆盖固定允许集合：解析并校验协议、数字主机、端口和精确路径，拒绝用户信息、fragment、query 和其他地址。不要通过去掉尾斜杠或修改大小写合并不同路径。

由用户在任务配置中显式选择 endpoint ID，服务端映射为固定 URL 并创建 RunAsset 快照。不能从模型生成的字符串自动扩展执行范围。旧 sample_endpoint 身份与新 HTTP 资产分开，原模式继续可用。

## 7. 请求留痕与工具结果

暂时复用现有 ToolCall 存储与详情页，输出结构化结果，至少保存：

| 字段 | 含义 |
| --- | --- |
| 请求信息 | 工具调用 ID、资产 ID、GET、实际 URL、开始时间 |
| 响应信息 | HTTP 状态、响应头、保存的响应正文、收到响应时间与耗时 |
| 完整性信息 | 保存字节数、是否截断、编码或展示转换说明 |
| 错误信息 | 稳定错误类型与必要说明 |

单次总超时建议 5 秒，响应头与正文均设置大小上限，正文初始上限可设为 64 KiB。读取上限加一字节判断是否超限，不无限读取后再截断；禁止自动解压带来无界内存使用。

HTTP 404 或 500 仍然是实际取得的响应：工具可以成功完成传输并把状态码交给模型。连接失败、超时、范围拒绝与取消需要分别记录，不能伪装成一个正常 HTTP 状态。

正文截断时明确显示“保存了部分响应”。未知的完整长度保持未知，不能把保存长度或不可信的 Content-Length 当成实测总长度。若另做给模型的摘要，证据保留的是受限保存的原始数据；摘要不能覆盖它。二进制内容可拒绝或有界编码，不假装为完整文本。

演示工具不发送凭据，避免把密钥或模型配置混进 HTTP 记录。网页内容作为数据展示，不执行返回的 HTML 或脚本。

## 8. 接入已有执行与证据流程

增加一种工作类型，例如 `inspect_http_endpoint`，使用现有 Worker Session、Attempt、总预算、停止与超时流程。模型工具调用仍在预算内；被拒绝的请求也计入工具请求预算。

创建一个小型的证据来源解析边界：

- read_sample 的成功调用可以证明对应样本来源。
- get_endpoint 的成功调用可以证明对应真实 HTTP 资产来源。
- source 解析由程序验证调用的实际参数、已保存输出与当前 Attempt/Session/Run，不依靠模型指定目标。

不要把现有 read_sample 白名单直接改成“任意成功工具都可用作证据”。记录观察时仍需验证资产归属和来源类型。

模型可以报告状态码、标题、Content-Type 等观察。响应正文属于不可信输入；其中即使包含“忽略目标并访问其他地址”等文本，也不能改变工具范围和权限。不要把网页正文提升为 system 指令。

本阶段不自动确认漏洞；观察、传输成功和安全结论分别表达。新工具超时后按已有策略有限收尾，不通过自动重试掩盖不确定性。

## 9. 固定演示与界面

在创建任务时选择“内置样本”或“本地 HTTP 应用”。真实 HTTP 模式从白名单选择一个或多个端点；模型模式单独选择 Mock 或已配置的真实 Provider。

Planner 派发三个端点读取工作，Worker 实际请求 fixture 并保存观察，汇总工作读取这些结果，最终报告附可打开的证据来源。

资产详情与 Run 详情复用第四阶段页面；调用详情显示真实 URL、时间、响应状态、响应头、正文和截断提示。原始响应与模型整理的观察分开呈现。

再次运行前修改 fixture 的版本号。同一 `/health` 资产复用身份，两个 Run 保留各自响应与观察。不要修改第一次执行的历史内容。

## 10. 验收与实现任务

让实现 Agent 在本项目连续完成以下任务，保持每一步可运行：

1. 修正第 3 节的范围、停止竞争与错误 ID 问题。
2. 增加 fixture、HTTP 资产与 get_endpoint，复用现有架构与日志。
3. 增加 Mock 驱动的真实 HTTP 闭环、前端选项和证据展示。
4. 交付迁移、启动方法、必要测试、实际结果与未验证部分。

必要测试使用本地 HTTP 测试服务和独立 TEST_DATABASE_URL，测试端口通过受控测试配置注入，不能因此开放生产工具的任意目标输入。至少验证：

- 空范围、错误范围、未关联工作与范围外资产在发送请求前被拒绝，服务端计数为零。
- 重定向不被跟随；Location 指向的第二个本地服务计数为零。
- 正常响应、404、500、慢响应、连接失败与正文超限结果可区分。
- 停止能取消 HTTP 请求，不再产生后续工具调用或新观察。
- 错误来源资产、跨 Run 和跨 Session 绑定被拒绝。
- 同一资产两次执行响应不同，旧证据不被覆盖。
- 旧 fake、样本、单 Agent 和编排模式继续工作。

已有后端回归与前端类型检查通过后，记录一次实际页面演示结果。真实模型验证与 Mock 驱动验证分别报告，没有凭据时明确写未验证。

学习验收：负责人能够解释“模型请求工具与真正发送 HTTP 的区别”“为什么工具只接受资产 ID”“为什么 404 不是连接错误”，并能在页面找到一次实际请求的证据。
