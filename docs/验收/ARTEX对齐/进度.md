## 与 ARTEX 有意不同的部分

1. ARTEX Worker 使用 SDK 的 transcript/compaction；这里是 PostgreSQL 原始消息、完整产物和确定性的协议块提取式检查点。它能安全缩短旧上下文，但不等同于 SDK 的语义总结能力；单个不可分割新交互过大时会明确失败。
2. ARTEX Planner 的 TodoStore 在进程内共享；这里持久化，配合恢复与审计。Epoch、总额度硬上限、追加授权账本也属于本工程适配。
3. 暂停采用在线屏障并保持当前 Attempt；停止/耗尽/关机后的恢复采用显式 Epoch。已发出的外部请求不承诺撤回，也不保证副作用恰好执行一次。
4. 类型资产从已授权 HTTP 快照推导，不代表端口扫描或权限扩展。完整产物覆盖已注册工具；没有宣称任意工具都经过 HTTPS 流量代理录制。
5. 已实现 MCP/skills 类能力的注册扩展边界并用本地适配器验收；尚未连接具体外部 MCP 服务、技能包或通用 Shell，这些不是本轮验收前置。
6. `verified` 核验来源与状态，不能自动证明任意漏洞描述和自然语言目标。旧报告可缺少显式复测条件；此时不能自动判 fixed。人工审核、来源、修复处置分别保留。
7. 新复合外键采用 NOT VALID：约束新写入，不会伪造或自动修补旧关联；这不表示所有历史坏数据已经逐行审计。
