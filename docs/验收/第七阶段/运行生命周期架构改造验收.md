# 运行生命周期架构改造验收

## 问题与改造

排查线索是 Run `0b880624-0318-4990-b02a-6f8054fb74b9`：预算耗尽后父 Run 已失败，但仍有 running 工作与 Attempt，以及 pending 工作。原预算检查位于调度循环，原收尾函数又跳过终态父 Run，形成状态收尾缺口。

原链接深度 SQL 使用无防环的 `UNION ALL`，且忽略深度查询错误。在双向导航关系下存在无界递归风险。现场三次工具执行都在约 5 秒后报连接关闭，与工具超时吻合。本次没有在开发数据库重放旧查询或重新访问靶场；本地成环图回归验证修复后的行为。

本次完成：

- 集中模型/工具额度申请，探索不占用预留的 1 次总结额度，总额度不可超限。
- 最后一次合法调用及 Worker 最终写入完成前，不提前终止父 Run。
- 收尾关闭探索准入，广播具名取消，等待上限 5 秒，然后执行独立有界的数据库清理。
- 单 Agent、Engine、模拟执行器、启动恢复、执行器拒绝启动和配置错误共用终态服务。
- 父 Run 已终态时也能幂等清理子记录，保留原结果和结束原因。
- 创建会话/模型调用/工具调用/消息与终态事务使用父行锁串行化，拒绝迟到的活动记录；调用完成写入不能覆盖 interrupted。
- 一次无工具的预留总结请求；失败、取消或超时时保存程序化部分结果与证据引用。
- 种子字段、受限最短路径查询、成环去重、较短路径更新，以及查询错误即时返回。
- 真实靶场测试显式 opt-in，默认测试不访问靶场。

设计和状态语义见 `docs/运行生命周期预算与任务收尾设计.md`。

## 核心回归

新增测试：

- `TestBudgetConcurrentAdmissionAndReservedSummary`：64 个竞争者争最后探索额度；总结额度受总上限限制。
- `TestBudgetSettlementAndDeadlineBlockAdmission`：收尾、取消、过期均拒绝新探索调用。
- `TestLifecycle_LastAllowedCallAndSummaryFallback`：最后一次探索调用仍在执行时 Run 保持运行；结果写入保留；总结成功及失败两种路径均有部分结果。
- `TestLifecycle_TerminalParentRepairAndLateWrites`：终态父项补齐清理，重复执行安全，迟到工作/模型/工具写入不能复活状态。
- `TestLifecycle_StartupRecoveryPreservesStopIntent`：重启恢复保留已经持久化的用户停止意图。
- `TestLifecycle_BoundedDrainAndLateProviderResponse`：故意忽略取消的 fake 模型不阻止 Run 在宽限后结束；迟到返回的工具请求不执行。
- `TestLifecycle_ConcurrentFinalizationPreservesWinner`：完成、超时和停止并发；第一位终态写入者保持稳定。
- `TestLifecycle_RejectedExecutorDoesNotLeaveQueuedRun`：Manager 拒绝启动时 Run 不占用活动槽位。
- `TestDiscoveryGraph_CyclesMultipleSeedsAndShorterPaths`：已有证据模拟互链、自链接、重复链接、多种子、较短路径和深度边界，无网络请求。

原有会话隔离、Responses 持久化、HTTP 证据、编排、停止竞争及重启恢复检查继续执行。模拟执行器停止原因改为标准 `user_requested_stop`，进程关闭/重启原因为 `shutdown`；相应测试按新语义更新。

## 实现边界

- 单进程执行；未实现多副本租约或外部副作用的自动重放。
- 忽略 context 的 goroutine 无法被 Go 强制杀死；Run 的等待有界，迟到写入有终态保护。
- 数据库完全不可用时无法承诺即时持久化；错误显式暴露，保留重启恢复路径。
- 深度迁移回填种子字段；历史图的最短深度在后续成功的发现事务中刷新。
